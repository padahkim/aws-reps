# chapter-audit 지적·판정 형식 — 정본

세 검수 에이전트(fact·consistency·learner-auditor)와 finding-verifier가 **같은 형식**으로 쓰고 읽는다.
형식이 갈리면 3단계 병합에서 메인이 지적을 다시 해석해야 하고, 그 해석이 곧 오류 지점이 된다.

> 이 문서와 에이전트 정의에는 **특정 챕터의 실제 결함을 예로 넣지 않는다.** 회귀 테스트(#300)가
> 과거 검수 결과를 정답으로 쓰므로, 예시에 그 결함이 있으면 정답이 프롬프트로 새어 측정이 무의미해진다.
> 예시는 가상의 문장으로만 든다.

## 1. 유형 코드

한 지적에는 결함 하나, 유형 하나. 두 유형에 걸치면 **교정 행동을 결정하는 쪽**을 고른다
(예: 그림이 본문과 반대이고 본문이 맞다 → C2. 본문도 공식 문서와 다르다 → 따로 F1).

### F — 사실 (fact-auditor): 챕터 ↔ AWS 공식

| 코드 | 이름 | 판정 기준 |
|---|---|---|
| F1 | 사실 오류 | 공식 문서와 값·동작이 다르다 (한도·기본값·수명·누가 무엇을 호출/검증하는가) |
| F2 | 근거 없는 주장 | 원장(`VERIFIED_FACTS`)·공식 문서 어디에도 없다. **거짓이라는 뜻이 아니다** — 교정은 약화·삭제·실측 중 하나 |
| F3 | 낡은 명칭·경로 | 기능 개명·콘솔 메뉴 경로·옛 기본값. 시험 지문은 옛 이름을 쓸 수 있으니 기본 교정은 "병기" |
| F4 | 조건부를 기본처럼 | 특정 플랜·설정·흐름에서만 되는 것을 무조건처럼 쓴다 |

### C — 일관성 (consistency-auditor): 챕터 ↔ 챕터 자신

| 코드 | 이름 | 판정 기준 |
|---|---|---|
| C1 | 자리 간 모순 | 같은 대상에 대한 서술이 본문·그림·카드·셀프 퀴즈·outro·meta·선행 챕터 사이에서 어긋난다 — 학습자가 두 자리를 다 읽으면 다른 그림을 갖게 된다 |
| C2 | 그림↔본문 불일치 | 화살표 방향·단계 순서·단계 문구·"누가 무엇을 받는가"가 본문 핵심 문장과 다르다 |
| C3 | 참조·번호 오류 | "§N에서 …" 예고가 §N 내용과 다르다, "N번째 항목"이 실제 순서와 다르다, 부제의 단계 수가 실제와 다르다 |
| C4 | 부분 교정 잔재 | 같은 대상을 두 구도로 말하는 흔적 — 한쪽만 나중에 고쳐졌다 |
| C5 | 중복 반복 | 같은 단서·경고가 3자리 이상, 또는 거의 같은 문장이 2자리 이상 (outro가 본문 요점을 되짚는 의도된 복습은 제외) |

### L — 학습자 경로 (learner-auditor): 챕터 ↔ CLAUDE.md Audience

| 코드 | 이름 | 판정 기준 |
|---|---|---|
| L1 | 정의 전 사용 | 설명한 적 없는 용어·개념을 전제한다 (앞 챕터에서 정의됐거나 "→ §N에서 다룬다" 예고가 있으면 위반 아님) |
| L2 | 준 적 없는 재료 요구 | 카드·셀프 퀴즈의 정답, ExamPoint·Note·outro의 주장이 그 섹션까지의 본문에 없다 |
| L3 | 시험 메타지식 인출 | 출제 경향·함정 유형·정답 패턴을 **묻는다** (CLAUDE.md Audience — 정답이 본문에 있는 사실에 시험 프레이밍만 씌운 것은 적법) |
| L4 | 순서·논리 흐름 | 전제보다 결론·경고가 먼저 온다, 대조·인과 접속어가 실제 관계와 안 맞는다, 이유 없이 결론만 있다 |
| L5 | 비중 | DVA-C02 범위·챕터 목표에 비해 지면이 과하거나 모자라다 (반복 횟수만으로 판정하지 않는다) |
| L6 | 설명 공백 | 결과만 말하고 메커니즘(누가·무엇으로·왜)이 없어서, 챕터 목표나 카드·퀴즈가 전제하는 이해에 학습자가 닿지 못한다 |

## 2. 규모 — 보고서 묶음을 정한다

| 값 | 뜻 | 보고서에서 |
|---|---|---|
| 문장 | 답이 정해진 문장·값·표 행 단위 교정 | 문장 교정 묶음 (이슈 1개) |
| 구조 | 개념 도입·그림 재작도·섹션 재배치·여러 자리를 한 기준으로 다시 맞춤 | 주제·섹션·그림 단위 묶음 (이슈 여럿) |
| 실측 | 문서로 판정이 안 나서 실제 계정으로 확인하거나 사용자가 정해야 한다 | 건별 |

## 3. 검수 파일 형식 — `01_<agent>_findings.md`

````markdown
# <agent> — <챕터 id> @ <대상 커밋 short sha>

- 읽은 파일: `sections/01.mdx`(34) · `sections/02.mdx`(41) · … · `session.ts`(260)   ← 스코프 목록과 대조된다. 못 읽은 파일은 이유와 함께
- 외부 근거: VERIFIED_FACTS 적중 n · 문서 조회 m · 조회 실패 k   ← fact-auditor만
- 대조한 주장 수: N   ← fact-auditor만 (맞은 주장도 센다 — 지적 0건이 "안 봤다"와 구분된다)
- 지적: N건 (유형별: F1 2 · F2 1 …)

## F-01 — <한 줄 요약>
- 유형: F2
- 규모: 실측
- 위치: `sections/05.mdx:12` · `selfquiz.ts:88 (sq-foo-bar, §05)` · `session.ts:140 (c9)`
- 원문: > 가상의 예: "X 기능은 같은 계정 안에서만 동작한다"
- 문제: 무엇이 왜 문제인가 — 2~3문장
- 근거: `VERIFIED_FACTS.md:<행>` 또는 URL (C·L 계열은 대조한 챕터 내 위치)
- 교정 방향: 1~2문장. C1이면 어느 자리를 기준으로 맞출지 후보를 적는다
- 확신도: 높음 | 중간 | 낮음
````

- **ID 접두**: fact `F-`, consistency `C-`, learner `L-`. 번호는 파일 안에서 01부터.
- **위치**: 대상 챕터 디렉터리 기준 상대 경로. 줄 번호는 **직접 연 파일에서 확인한 값만** 쓴다. 카드·퀴즈는 줄 번호와 함께 `id`·`slug`·섹션 번호를 괄호로 적는다 — 줄은 편집으로 밀려도 id는 남는다. 같은 결함이 여러 자리에 있으면 **한 지적에 전부** 적는다.
- **원문**: 그대로 인용한다 (요약·의역 금지 — 검증자가 문자열로 찾는다). 길면 핵심 구절만.
- 선행 챕터 위치는 `ch0-2/sections/04.mdx:30`처럼 챕터 id를 앞에 붙인다.

## 4. 판정 형식 — `03_finding-verifier_<batch>_verdicts.md`

````markdown
# finding-verifier — <챕터 id> 배치 <b1> (A01~A12)

- 판정: confirmed n · refuted n · uncertain n

## A03 — confirmed
- 실재: 있음 (`sections/05.mdx:12` — 원문 일치) | 줄 어긋남 → 실제 `:14` | 없음
- 반박 시도: 세운 반론과 그것이 무너진/성립한 이유 — 2~3문장
- 근거: 직접 연 URL·파일:줄
- 교정 방향 보정: (제안대로 고치면 다른 자리와 새 모순이 생길 때만)

## A04 — uncertain
- …
- 판정 조건: 무엇이 정해지면 판정되는가 한 줄 (예: "실제 계정에서 X를 시도해 응답 코드 확인")
````

- `confirmed` — 실재·의미·근거·범위 검사를 모두 통과했다. 반박을 시도했으나 실패했다.
- `refuted` — 원문이 없다, 문맥상 문제가 아니다(바로 뒤에 조건이 있다·앞에서 정의했다·의도된 비유), 근거가 지적과 반대다, DVA-C02·챕터 목표 범위 밖 디테일을 요구한다. 사유를 한 줄로.
- `uncertain` — 판정에 문서 밖 사실 확인(실측)이나 사용자 결정이 필요하다. **확신이 없다고 confirmed로 올리지도 refuted로 버리지도 않는다.**
- `unverified` — 지적 형식이 깨져(위치·원문 없음) 판정 자체를 못 했다. 기각이 아니다 — 오케스트레이터가 "미검증"으로 보고한다.
