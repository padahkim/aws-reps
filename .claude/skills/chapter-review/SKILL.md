# /chapter-review — 챕터 언어 품질 검수

목표: 챕터 텍스트에서 **번역투 문장과 용어 불일치**를 잡아 관용적 한국어로 교정한다.
이 리포의 챕터는 영어 원본 자료 기반 변환이라 번역투가 **구조적으로** 발생한다 (#79).
챕터 완료 시마다 1회 돌리는 언어 품질 게이트이며, #29(잔여 24챕터)에서 반복 재사용된다.

**검수 축은 언어 품질 하나뿐이다.** 내용 누락·구성·문제 배치·원본 대조는 이 스킬이 다루지
않는다 — 그건 #45류 검수 이슈의 축이다. 두 축을 섞으면 어느 쪽도 끝까지 못 본다.

## 입력·범위

- **입력**: 챕터 id 하나 (`ch0-1`·`ch1-2` 등). 없이 호출되면 어느 챕터인지 먼저 묻는다.
- **스캔 대상 = 그 챕터의 학습자 노출 한국어 텍스트 전부**. `content/chapters/<id>/` 아래:
  - `intro.mdx`·`outro.mdx`·`sections/*.mdx` — 본문 산문
  - `body.tsx`·`figs.tsx` — JSX 안의 한국어 문자열(문단·그림 캡션·라벨)
  - `drills.ts` — 퀴즈 문항·선택지·해설(`title`·`question`·`explanation` 등)
  - `session.ts` — 인출 세션 카드의 질문·답·심화 질문(`q`·`a`·`why` — 셋 다 학습자에게 렌더된다, `section-concepts.tsx`)
  - `selfquiz.ts` — 섹션 셀프 퀴즈의 `q`·`a` (#98. 인출 카드 아래 같은 페이지에 렌더된다 —
    `app/chapters/[id]/[sec]/page.tsx`. 2026-07-28 ch0-2 소급에서 목록 누락이 드러나 추가)
  - `meta.ts` — 챕터 제목·설명
- **스캔 제외**: import 문, 컴포넌트 이름, `id`/`ap-northeast-2` 같은 코드·식별자, 영어 원어 병기(`가용영역(AZ)`의 AZ 등)는 대상이 아니다.

### drills.ts는 생성물 — 읽되 손편집 금지 (2026-07-23 소급 실행에서 확정)

`drills.ts`는 **업스트림 `aws-cloud-drills`에서 `scripts/import-drills.ts`로 생성**된다
(파일 헤더에 "생성물 — 손편집 금지" 명시). 그래서 drills의 번역투·용어는 **읽어서 검사는
하되(용어 일관성 비교에 필요), 이 리포에서 직접 고치지 않는다** — 재임포트가 덮어쓴다.

- drills에서 발견한 위반은 **"업스트림 후속"으로 분류**해 후보 표에 별도 표기하고,
  실제 교정은 `aws-cloud-drills`의 원본 JSON을 고쳐 재임포트하는 별도 이슈로 넘긴다.
- **본문을 고쳤는데 같은 표현이 drills에도 있으면** 본문/drills 표기가 어긋난다 — 이
  불일치를 보고에 명시하고 업스트림 후속으로 남긴다 (본문만 고치고 침묵하면 다음 검수가
  "왜 drills만 다르지"를 다시 파낸다).
- 마찬가지로 생성물인 `*/quiz` re-export도 손대지 않는다. 편집 대상은 손저작 자산
  (`*.mdx`·`body.tsx`·`figs.tsx`·`session.ts`·`selfquiz.ts`·`meta.ts`)뿐이다.
- **용어 계열이 통째로 다를 수 있다** (2026-07-28 ch0-2에서 확인): iam.json 드릴은 `역할`(67)·
  `IAM 사용자`(24)로, 본문 하우스 표기(`롤`·`IAM 유저`)와 낱말 하나가 아니라 **계열 전체**가
  어긋나 있었다. 이런 건 본문 쪽을 드릴에 맞추는 게 아니라 **본문 하우스 표기로 통일하고
  드릴 정렬은 #93에 넘긴다** — 어느 쪽이 정본인지는 본문이 정한다.

## 검수 체크리스트 — 정본

번역투는 "틀린 문법"이 아니라 "영어 문장 구조가 한국어에 그대로 배어난 어색함"이다.
아래는 이 리포 콘텐츠가 영어 원본에서 변환되며 반복해 나타나는 패턴이다. **각 항목은
기계적 금지어가 아니라 후보 신호다** — 잡아서 보고, 관용 표현이거나 의도된 비유면 남긴다.

### A. 번역투 문장 패턴

| # | 패턴 (영어 원인) | 예 → 교정 |
|---|---|---|
| A1 | **무생물 주어 + 능동** ("This service provides/allows/enables") | "이 기능은 암호화를 제공한다" → "이 기능으로 데이터를 암호화할 수 있다" / "…를 암호화한다" |
| A2 | **추상명사 + 구체 동사 부조화** ("what scope do they live in") | "이 리소스는 어느 범위에 **사는가**" → "이 리소스의 **범위는 어떻게 되는가**" / "어느 **레벨**(글로벌·리전·AZ)에 **속하는가**" / "어느 **단위**에서 생성·동작하는가" |
| A3 | **과도한 피동** ("is managed by", "can be") | "A는 B에 의해 관리된다" → "B가 A를 관리한다"; "설정될 수 있다" → "설정할 수 있다" |
| A4 | **부정관사 직역 "하나의"** ("a/an") | "하나의 버킷을 만든다" → "버킷을 만든다" / (수가 핵심이면) "버킷 하나를 만든다" |
| A5 | **대명사 직역** ("it/this/they") | "그것은 리전 단위다" → (주어 생략) "리전 단위다" / (지시 대상 명시) "S3는 리전 단위다" |
| A6 | **"~에 대해/대한" 남용** ("about/for/regarding") | "권한에 대해 정의한다" → "권한을 정의한다"; "요청에 대한 서명" → "요청 서명" |
| A7 | **"~을 가진다/가지고 있다"** ("has") | "정책은 여러 문을 가진다" → "정책에는 여러 문이 있다" |
| A8 | **"~라는 사실/것"** ("the fact that") | "암호화된다는 사실이 중요하다" → "암호화된다는 점이 중요하다" / "암호화된다는 게 핵심이다" |
| A9 | **"~와 같은" 남용** ("such as") | "S3와 같은 서비스" → "S3 같은 서비스" / "예를 들면 S3" |
| A10 | **직역 지시문** ("make sure to / note that / keep in mind") | "~하는 것을 확인하라" → "~해야 한다"; "~라는 점에 주목하라" → "~라는 점을 짚고 가자" |
| A11 | **"당신/여러분은 ~할 수 있다"** ("you can") | "당신은 롤을 붙일 수 있다" → (주어 생략) "롤을 붙일 수 있다" |
| A12 | **미래시제 직역** ("will") | "요청은 거부될 것이다" → "요청은 거부된다" |
| A13 | **긴 관형절 어순 직역** — 수식어를 명사 앞에 길게 쌓아 올린 영어 어순 | 한 문장이 관형절 2겹 이상이면 문장을 끊어 서술로 편다 |
| A14 | **"~할 가치가 있다"** ("worth ~ing") | "두 개는 외워둘 가치가 있습니다" → "두 개는 외워두세요" / "꼭 외워둘 두 개는" |
| A15 | **영어 복수 "-들" 직역** ("tools/services") — 수가 이미 드러나면 한국어는 복수를 표시하지 않는다 | "줄여나가는 도구들, 그리고" → "줄여나가는 도구, 그리고" (단, "이들의 교집합"처럼 대명사로 쓰인 "들"은 위반 아님) |
| A16 | **삽입구가 조사 앞을 끊음** — 영어 동격 삽입(`— … —`)을 한국어 어순 그대로 옮겨 "명사 — 삽입구 — 과 구분됩니다"가 되는 형태 | 삽입구를 문장 뒤로 뺀다: "…방식과 구분됩니다 — …이 대표적입니다" |

### B. AWS 한국어 용어 기준

- **정본 = AWS 공식 한국어 콘솔·문서 용어.** 헷갈리면 그 표기를 따른다 (예: Region→리전,
  bucket→버킷, instance→인스턴스, managed→관리형, 프로비저닝).
- **번역 선택이 갈리는 핵심어**:
  - reside / live in → **속하다·위치하다** (기본). "산다"는 의도된 비유일 때만 (아래 주의).
  - scope → **범위**, level → **레벨/계층**, unit → **단위**
- **확정 표기** (2026-07-28 ch0-2 소급에서 사용자 결정 — 흔들리면 여기를 따른다):
  - credential → **자격 증명** (띄어쓴다). AWS 공식 표기이고, 같은 페이지에 렌더되는 drills가
    전부 띄움이다. 붙임 "자격증명"은 위반 — ch0-1·ch1-1에 남아 있는 붙임은 후속 정렬 대상.
  - role → **롤**, user → **유저** (하우스 표기). 단 AWS 콘솔 고유 명칭인 **"루트 사용자"**,
    **"Lambda 실행 역할"** 은 그대로 두고, 앱 최종 사용자를 가리키는 "사용자"도 다른 뜻이라 유지.
  - Credential Report → 영문은 **단수** `Credential Report` (AWS 공식), 한국어는 자격 증명 보고서.
- **영어 원어 병기**는 최초 등장에서 `가용영역(AZ, Availability Zone)`처럼 하고 이후는 한국어(또는 약어)로 통일한다.
- **챕터 내 표기 일관성**을 본다: 같은 개념이 한 챕터에서 다른 표기로 흔들리지 않는가
  (예: "가용영역"과 "가용 영역" 혼용). 리포에 이미 자리잡은 하우스 표기가 있으면 그쪽으로
  통일하되, AWS 공식과 어긋나는 표기를 새로 만들지는 않는다.

### 주의 — 비유·리듬은 죽이지 않는다

번역투 교정의 목적은 **관용성**이지 획일화가 아니다. 다음은 위반이 아니다:

- **의도된 비유**: ch0-1의 "리전/AZ는 내 리소스가 **사는 집**, 엣지는 편의점 진열대"는
  일부러 세운 비유다. 비유 안의 "산다"는 살린다 — A2가 겨냥하는 건 비유 없이 추상명사에
  구체 동사를 얹은 "**범위**에 사는" 쪽이다.
- **구어체 리듬**: "자, 그럼 시작해 볼까요?" 같은 말맛은 번역투가 아니다.
- 확신이 안 서면 교정하지 말고 **후보로만 올려 사용자 판단에 맡긴다**.

## 절차

1. **입력 확인** — 챕터 id. 없으면 묻는다. `content/chapters/<id>/`가 있는지 확인.
2. **스캔** — 위 스캔 대상 파일들의 한국어 텍스트를 읽고, A·B 체크리스트로 위반 후보를
   모은다. grep은 후보를 좁히는 보조 수단일 뿐, 실제 판정은 문장을 읽고 한다 (기계적
   금지어 매칭이 아니다).
3. **후보 제시** — 사용자에게 표로 낸다. 각 후보에 **파일:줄, 원문, 교정안, 근거(A1~B)**를
   함께. 확신도가 낮은 건 그렇게 표시한다. **여기서 멈추고 사용자 확인을 받는다 — 확인
   없이 반영 금지.** (비유·의도적 표현을 잘못 건드릴 수 있으므로.)
4. **반영** — 사용자가 승인한 후보만 Edit로 반영한다. 부분 승인이면 승인분만.
5. **피드백 루프** — 스캔 중 A·B에 없던 새 번역투 패턴을 발견하면, 반영과 함께 이 SKILL.md의
   체크리스트에 **역반영**한다 (다음 챕터부터 그 패턴도 잡히도록). 이게 24챕터에 걸쳐
   체크리스트를 성숙시키는 장치다.
6. **검증** — `npm run validate`와 빌드가 통과하는지, 프리뷰에서 수정 챕터가 정상 렌더되는지
   확인한다 (MDX/JSX 문자열을 고치므로 파싱이 깨질 수 있다).
