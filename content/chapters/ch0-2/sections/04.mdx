<CodeBlock>{`{\n  "Version": "2012-10-17",          // 정책 언어 버전 — 항상 이 값 (필수)\n  "Id": "S3-Account-Permissions",   // 정책 식별자 (선택)\n  "Statement": [{\n    "Sid": "AllowS3Read",           // 문장 식별자 (선택)\n    "Effect": "Allow",              // Allow 또는 Deny (필수)\n    "Principal": {                  // "누가" — 리소스 기반 정책에서 사용\n      "AWS": ["arn:aws:iam::123456789012:root"]\n    },\n    "Action": ["s3:GetObject"],     // 허용/거부할 API 동작 (필수)\n    "Resource": "arn:aws:s3:::my-bucket/*",  // 대상 ARN (필수)\n    "Condition": {                  // 적용 조건 (선택)\n      "IpAddress": { "aws:SourceIp": "10.0.0.0/16" }\n    }\n  }]\n}`}</CodeBlock>

<Note>ARN 형식: <Code>arn:aws:service:region:account-id:resource</Code>. S3처럼 글로벌한 리소스는 region/account 자리가 비어 있습니다.</Note>

<SubTitle>정책 상속 — 유저가 실제로 받는 권한</SubTitle>

- 그룹에 연결된 정책은 **그룹의 모든 구성원**에게 적용됩니다
- 여러 그룹에 속한 유저는 <b>모든 그룹의 정책을 합쳐서</b> 받습니다
- 그룹 미소속 유저에게는 **인라인 정책**을 직접 연결할 수 있습니다

<SubTitle>Condition — 조건부 허용의 재료</SubTitle>

자주 나오는 전역 조건 키 두 개는 외워둘 가치가 있습니다: <Code>aws:SourceIp</Code>(요청 IP 제한)과 <Code>aws:MultiFactorAuthPresent</Code>(MFA 없으면 거부). 한 단계 더 들어가면 **앱 수준의 세분화 인가**도 Condition으로 구현합니다 — 예를 들어 <Code>dynamodb:LeadingKeys</Code> 조건 키로 “각 사용자는 자기 파티션 키로 시작하는 항목만 읽기” 같은 사용자별 행 단위 접근 제어를 정책 한 장으로 걸 수 있습니다.

<SubTitle>정책 변수 — 동적 정책 (Dynamic Policy)</SubTitle>

사용자 100명에게 각자의 홈 디렉터리만 허용하려면, 정책을 100개 만들 필요 없이 <b>정책 변수</b> <Code>{"${aws:username}"}</Code>를 쓴 정책 1개로 해결합니다.

<CodeBlock>{`{\n  "Effect": "Allow",\n  "Action": ["s3:*"],\n  "Resource": ["arn:aws:s3:::my-company/home/\${aws:username}/*"]\n}`}</CodeBlock>

<ExamPoint>
  <ExamLi>정책 JSON을 읽고 <b>허용 여부를 판독</b>하는 문제 — Effect·Action·Resource 매칭과 Deny 우선 규칙이 재료</ExamLi>
  <ExamLi><b>Principal은 리소스 기반 정책에만</b> — “IAM 유저에 붙이는 정책에 Principal이 필요하다”는 오답</ExamLi>
  <ExamLi>“사용자마다 자기 폴더/자기 항목만” → <b>정책 변수 <Code>{"${aws:username}"}</Code></b> 또는 <Code>dynamodb:LeadingKeys</Code></ExamLi>
  <ExamLi>Version 값은 <b>2012-10-17 고정</b> — 최신 날짜로 바꾸는 선택지는 함정</ExamLi>
