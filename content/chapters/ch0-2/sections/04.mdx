모든 권한은 이 JSON 구조로 표현됩니다. 시험에서 정책을 보여주고 “이 요청은 허용되는가?”, “이 유저는 무엇을 할 수 있는가?”를 판독하는 문제가 최빈출이므로 필드 하나하나를 확실히 익혀둡니다.

  <InfoCard tone="amber" title="Action" sub="필수"><Code>service:Operation</Code> 형식. <Code>s3:GetObject</Code>, <Code>dynamodb:PutItem</Code> 등. 와일드카드 <Code>{"*"}</Code> 사용 가능 (<Code>{"s3:*"}</Code>).</InfoCard>
  <InfoCard tone="red" title="Resource" sub="필수">대상 리소스의 <b><Term id="arn">ARN</Term></b>. 버킷(<Code>:::my-bucket</Code>)과 객체(<Code>:::my-bucket/*</Code>)는 다른 ARN임에 주의.</InfoCard>
  <InfoCard title="Principal" sub="리소스 기반 정책에서">이 정책이 적용될 계정/유저/역할 — “누가”. 자격 증명 기반 정책에는 없습니다(주체가 곧 연결 대상).</InfoCard>
  <InfoCard tone="teal" title="Condition" sub="선택">정책이 발효되는 조건 (IP, 시간, MFA 여부, 태그 등). 아래 “조건부 허용의 재료” 참고.</InfoCard>

<PointBox tone="amber" title="ARN 형식">외워두세요: <Code>arn:aws:service:region:account-id:resource</Code>. S3처럼 글로벌한 리소스는 region/account 자리가 비어 있습니다. 둘째 자리 <Code>aws</Code>는 표준 파티션 기준이고 GovCloud(<Code>aws-us-gov</Code>)·중국(<Code>aws-cn</Code>)에선 달라집니다 — 시험은 사실상 <Code>arn:aws</Code>만 나옵니다.</PointBox>

<SubTitle>정책 상속 — 유저가 실제로 받는 권한</SubTitle>

- 그룹에 연결된 정책은 **그룹의 모든 구성원**에게 적용됩니다
- 여러 그룹에 속한 유저는 <b>모든 그룹의 정책을 합쳐서</b> 받습니다
- 그룹 미소속 유저에게는 **인라인 정책**을 직접 연결할 수 있습니다

<SubTitle>Condition — 조건부 허용의 재료</SubTitle>

자주 나오는 전역 조건 키 두 개는 외워두세요: <Code>aws:SourceIp</Code>(요청 IP 제한)과 <Code>aws:MultiFactorAuthPresent</Code>(MFA 없으면 거부). 한 단계 더 들어가면 **앱 수준의 세분화 인가**도 Condition으로 구현합니다 — 예를 들어 <Code>dynamodb:LeadingKeys</Code> 조건 키로 “각 사용자는 자기 파티션 키로 시작하는 항목만 읽기” 같은 사용자별 행 단위 접근 제어를 정책 한 장으로 걸 수 있습니다.

여기까지의 재료 — Action·Resource ARN·Condition — 를 실제 판독에 써 봅니다. 시험이 내는 함정 둘(버킷 ARN vs 객체 ARN 불일치, 조건 불충족)이 그대로 들어 있습니다:

<SubTitle>정책 변수 — 동적 정책 (Dynamic Policy)</SubTitle>

사용자 100명에게 각자의 홈 디렉터리만 허용하려면, 정책을 100개 만들 필요 없이 <b>정책 변수</b> <Code>{"${aws:username}"}</Code>를 쓴 정책 1개로 해결합니다.

<CodeBlock>{`{\n  "Effect": "Allow",\n  "Action": ["s3:*"],\n  "Resource": ["arn:aws:s3:::my-company/home/\${aws:username}/*"]\n}`}</CodeBlock>

<ExamPoint>
  <ExamLi>정책 JSON을 읽고 <b>허용 여부를 판독</b>하는 문제 — Effect·Action·Resource 매칭과 Deny 우선 규칙이 재료</ExamLi>
  <ExamLi><b>Principal은 리소스 기반 정책에만</b> — “IAM 유저에 붙이는 정책에 Principal이 필요하다”는 오답</ExamLi>
