로그인 화면을 직접 만들지 않아도 됩니다. <b>Hosted UI</b>는 Cognito가 <b>로그인·가입·비밀번호 재설정 페이지를 대신 호스팅</b>해 주는 기능입니다 — 앱은 그 주소로 사용자를 리다이렉트하고, 인증 결과를 콜백에서 받습니다.

- 로고와 CSS로 <b>외관을 커스터마이징</b>할 수 있다
- 기본 주소는 <b>Cognito가 주는 도메인</b>이지만, <b>커스텀 도메인</b>(예: `auth.example.com`)으로 바꿀 수 있다
- 커스텀 도메인은 User Pool의 <b>“App Integration”</b> 섹션에서 설정한다

<Note>권장 방식인 <b>Authorization Code Grant</b>에서는 콜백에 토큰이 아니라 <Code>code</Code>가 옵니다. 앱이 그 코드를 <Code>/oauth2/token</Code> 엔드포인트에서 토큰으로 교환하며, <Code>openid</Code> 스코프를 요청했을 때 ID·Access·Refresh 토큰을 받습니다. <Code>openid</Code>가 없으면 <b>ID 토큰은 발급되지 않습니다.</b> 공개 클라이언트는 보통 <b>PKCE</b>로 코드를 보호합니다. <b>Implicit Grant</b>는 <Code>openid</Code> 요청 시 콜백에 ID·Access 토큰을 직접 붙이지만 <b>Refresh 토큰은 발급하지 않습니다.</b></Note>

<WarnBox>커스텀 도메인을 쓰려면 <b>ACM 인증서가 반드시 us-east-1(버지니아 북부)에 있어야 합니다</b>. 내 앱이 서울 리전에 있어도 인증서만은 us-east-1입니다 — 다른 리전에 만든 인증서는 Cognito 설정 화면에 <b>아예 목록에 뜨지 않습니다</b>. (ACM = AWS Certificate Manager, HTTPS 인증서를 발급·관리하는 서비스입니다.)</WarnBox>

<Note>같은 규칙이 <Term id="cloudfront">CloudFront</Term>에도 있습니다 — 전역 엣지에서 쓰이는 인증서는 us-east-1에 둔다는 공통 패턴이라, 둘을 세트로 외우면 헷갈리지 않습니다.</Note>

<ExamPoint>
  <ExamLi>“Hosted UI + 커스텀 도메인 + 인증서 위치” → <b>us-east-1</b>. 리소스가 있는 리전을 고르는 선택지가 오답으로 붙어 나온다.</ExamLi>
  <ExamLi>“로그인 화면을 개발하지 않고 붙이고 싶다” → <b>Hosted UI</b>.</ExamLi>
