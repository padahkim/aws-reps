로그인은 거의 모든 앱이 가장 먼저 만드는 기능이면서, 직접 만들면 가장 오래 발목을 잡는 기능이기도 합니다 — 비밀번호 저장, 이메일 확인, 비밀번호 재설정, MFA, 소셜 로그인, 토큰 만료. <b>Amazon Cognito</b>는 이 전부를 대신 맡는 관리형 서비스입니다. 쓰임새는 두 갈래인데 이 구분이 챕터 전체를 관통합니다 — 앱 사용자를 <b>로그인시키는</b> User Pool과, 로그인한 사용자에게 <b>AWS 리소스를 직접 만질 임시 열쇠를 쥐여 주는</b> Identity Pool입니다.

DVA-C02에서는 보안 도메인(Domain 2, 26%)의 핵심 서비스이고, 서버리스 아키텍처 문제의 배경으로도 계속 나옵니다 — API Gateway 앞단의 인증은 거의 항상 Cognito입니다. 강점은 사용자 수백만 명까지 그대로 확장되면서 서버를 한 대도 두지 않는다는 점이고, 주의점은 <b>두 풀의 역할을 뒤집어 놓은 선택지</b>가 함정으로 자주 쓰인다는 점입니다. 이 챕터는 개념 이해 중심이며 실습은 포함하지 않습니다.
