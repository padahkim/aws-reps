Lambda는 서버를 준비하지 않고 코드만 올려 실행하는 컴퓨팅 서비스입니다. 실무에서는 S3에 파일이 올라오면 썸네일을 만드는 이벤트 처리, API Gateway 뒤의 API 백엔드, SQS·Kinesis에 쌓이는 메시지 소비, EventBridge 스케줄로 도는 정기 작업처럼 “무언가 일어나면 잠깐 실행되는 일”의 표준 답안으로 쓰입니다. 이렇게 널리 쓰이는 이유는 분명합니다 — 서버 관리(패치·용량 산정)가 통째로 사라지고, 트래픽에 맞춰 알아서 확장되며, 실행한 시간만큼만 과금되어 놀 때는 비용이 0이기 때문입니다.

다만 만능은 아닙니다. <b>실행 15분 한도</b>, <b>콜드 스타트 지연</b>, <b>동시성 한도 초과 시 스로틀링</b> 때문에 장시간 작업이나 일정하게 빠른 응답이 필요한 곳에는 맞지 않으며, 시험도 바로 이 경계선을 즐겨 묻습니다. Lambda는 DVA-C02 Domain 1의 심장이고 배포·보안·트러블슈팅 도메인에서도 소재로 재등장하는 최중요 서비스입니다 — <b>호출 3유형(동기/비동기/이벤트 소스 매핑)의 구분과 각각의 오류 처리</b>, <b>동시성·콜드 스타트</b>, <b>버전·별칭·트래픽 전환</b>, 그리고 <b>수치 한도</b>가 반복 출제됩니다. 이 챕터는 S3 챕터(<ChLink id="ch1-1">ch1-1</ChLink>)의 이벤트 알림을 트리거 관점에서 다시 사용합니다.
