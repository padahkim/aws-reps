# 축1 리포트: cloudformation-dva-guide

**모드**: 레거시 / **평가 범위**: 부분 평가 (N/A: L1·L2·L7·L8 — 퀴즈 성분 없음) / **판정: 통과** (유효 총점 7/8 = 87.5%)

## 수정 지시

축1 유효 총점 87.5%(85%↑)로 **통과 — 축1 필수 수정 없음.** 종합 게이트는 축2 커버리지 갭이다(드리프트 감지·중첩 스택·변경 세트·SAM — 축2 「수정 지시」 1~4). 아래는 통과선 유지 상태에서의 선택적 상향안.

1. **[L6 상향 여지, 1→2, 선택]** 현재 역참조가 전부 동일 챕터 내부 링크·서비스 배경 언급뿐이다. **선행 커리큘럼 챕터를 명시 지목**하는 한 줄을 삽입하면 L6=2 인정 가능(근거로 실제 앞 챕터 번호·제목 인용 필수):
   - s209 서비스 역할 서두(2334–2348) / FigServiceRole의 `iam:PassRole`(1153): "**앞 IAM 챕터에서 배운 PassRole**(역할 전달 권한)을 여기 CFN 서비스 역할 위임에 적용" 식으로 선행 IAM 챕터를 명시 역참조.
   - s212 스택 정책 JSON(2499–2511)의 `Effect/Principal/Action/Resource` 구조: "**IAM 챕터의 정책 평가 로직(명시적 Deny 우선)과 동일 규칙**" 식으로 선행 챕터 지목.
   - s214 커스텀 리소스의 Lambda ARN·pre-signed S3 URL(2553–2560): "**앞 Lambda·S3 챕터의 ARN/사전 서명 URL 개념**을 여기서 결합"으로 명시.
2. **[구조 미세조정, L3 견고화]** `Exam` 콜아웃이 각 섹션 말단에 배치됨 — 최빈출 섹션(s203 Parameters·s207 내장함수·s211 DeletionPolicy, 모두 `l={3}` 빈출 상)만이라도 개념 카드 직후로 인터리브하면 인출 근접성↑. (감점 요인 아님 — 실코드·도식이 이미 인접해 L3=2 확보, 완성도 제안.)

## 보충 생성 목록 (결손 성분)

- **[퀴즈·해설 결손 — 최우선 산출물]** L1·L2·L7·L8 N/A의 원인. 변환 단계에서 채점형 문항+오답 조건화 해설 신규 생성 필요. **전환 소재 이미 풍부**: `Exam` 콜아웃 대부분이 "상황→정답" 실전 지문형이라 4지선다로 직접 전환 가능:
  - s200 변경 세트 vs 교체(1823–1827): "적용 전 변경 검토 → 변경 세트" / "업데이트 후 물리 ID 변경 → 교체(Replacement)" 판별 문항.
  - s203 Parameters(2065–2069): "비밀번호 콘솔 비노출 → NoEcho: true" / "항상 최신 AMI → SSM public parameter" / "현재 리전값 → AWS::Region" 함정 선지 문항.
  - s207 내장함수(2301–2306): !Ref(ID) vs !GetAtt(속성) vs !ImportValue(타 스택) vs !Sub(문자열 삽입) 4지선다 — 코퍼스 최상위 빈출 소재.
  - s210 Capabilities(2402–2406): 미승인 배포 → `InsufficientCapabilitiesException`; CAPABILITY_IAM vs NAMED_IAM vs AUTO_EXPAND 구분.
  - s211 DeletionPolicy(2474–2478): "데이터 남기고 스택 삭제 → Retain" / "삭제 전 백업 → Snapshot" / "RDS DBCluster 기본 Snapshot" 함정.
  - s212 스택 정책(2512–2516): **업데이트** 보호(스택 정책) vs **삭제** 보호(종료 방지·DeletionPolicy) 혼동 유발 문항.
  - s214 커스텀 리소스(2573–2578): "객체 든 S3 버킷 삭제 실패 자동화 → 커스텀 리소스(Lambda)+ServiceToken(같은 리전)" 문항.
  - s215 StackSets(2602–2605): "여러 리전+여러 계정 → StackSets" / Self-managed vs Service-managed 권한 모델 구분.
- **[해설 씨앗]** 각 `Exam`의 "왜 이 답인가"는 본문 `ul.pts`·`Note`·표에 분산 존재 → 오답별 조건화 해설로 재조립하면 L2 확보.
- **[최종 체크리스트 재활용]** `CHECKS` 14개 항목(1652–1667)이 이미 "지문 신호→정답" 압축 진술이라 각 항목을 O/X 또는 4지선다 씨앗으로 직접 전환 가능(L1 인출 밀도 확보의 최저난이도 경로).
- **[커버리지 — 축2 소관 위임]** 축2 「누락」: **드리프트 감지 전무·중첩 스택 간접·변경 세트 표면·SAM 고유 파트 부재**(축2 「수정 지시」 1~4). 학습 설계가 아니라 콘텐츠 커버리지 갭이므로 축1 채점엔 영향 없음 — 축2 소관으로 위임. 특히 SAM 갭은 배치 12(CDK)에서 제기되고 이 배치로 재확인된 4-3·4-4 인접 파일 공통 공백.

## 반복 약점 메모

- **L6 명시 선행-챕터 지목 부재** — 코퍼스 연속 L6=1(지금까지 전 파일 동일). 이 파일도 동일 챕터 내부 강의 링크(강의 211·214)·서비스 배경 언급(iam:PassRole·Lambda·S3)은 있으나 **선행 커리큘럼 챕터 통합 역참조가 0건**. 생성 프롬프트에 "IAM/Lambda/S3 등 앞 챕터 개념을 'N-N장에서 배운 X를 여기서 Y로 적용' 형식으로 최소 1회 명시 지목" 지시를 추가하면 코퍼스 공통 감점 해소 가능.
- **강점(유지)**: 개념 직후 **실코드(YAML/JSON)+SVG 도식+시나리오 Exam** 3중 인접(L3=2)과 강의 순번 원자화+정의표 부하관리(L4=2)는 코퍼스 L3·L4 설계 상위 기준선. 특히 실코드와 SVG가 모두 존재하는 조합은 messaging(코드 위주)·s3-SVG(도식 위주) 단독형보다 우위 — 중복/통합 판단 시 이 파일이 L3 기준 모델.
- **Exam 말단 배치**: 시나리오 콜아웃이 섹션 끝에 몰리는 구조는 messaging·s3 공통 — L3는 2 유지(실코드·도식 인접 덕)하나 인터리빙 여지 상존.

## 스키마 피드백 요약

- **템플릿 구조 해부(anatomy) 컴포넌트** — `.file`/`.file-row`(필수/선택 배지, 각 섹션 1줄 설명, 1863–1900)는 축2가 이미 `structureAnatomy[]{field, desc, required}` 신규 필드로 제안. 축1 관점 보강: 이 "구조 지도" 유형은 L4(인지부하) 저감 장치로 직결 — 전체 구조를 먼저 조망 후 각 섹션 심화하는 **개요→상세** 스캐폴딩이라 스키마에 학습 순서 메타(overview-first)로 태깅 가치.
- **빈출도(freq) 3단 태그** — `Freq`(l=3/2/1 → Bars 시각화, 각 `Sec`의 `l` 필드)는 코퍼스 최강 재현 스키마 요소(B7 계열). 인출 우선순위·간격반복 스케줄링 신호로 계속 누적.
- **완료 추적 체크리스트** — 말미 `ul.check` + 진행률 카운터(`doneCount`/`CHECKS.length`)는 축2가 `selfCheck[]{statement, freq}` 계열로 기록. 축1 관점: 빈출도 없는 순수 완료 추적형이라 채점형 아님(L1 N/A) — 스키마에 `gradable: bool` 플래그를 두면 L1 문항 vs 자가점검을 구분해 생성 파이프라인이 자동 판별 가능.
