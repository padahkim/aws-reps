## 수정 지시

축1 설계 점수는 통과 — 필수 설계 수정 없음. 아래는 L6 상향(1→2) 및 축2 사실 수정과의 연계 입력용(축1 감점 사유 아님).

1. **L6 강화(선택, 1→2)** — `SecStages` 스테이지 변수+Lambda alias 콜아웃(L584–589)에 "**1-x Lambda 버전·별칭** 챕터의 alias 가중 라우팅이 여기 통합 URI `${stageVariables.alias}`로 연결된다" 식 선행 챕터 명시 지목 추가. `SecAuth` IAM 행(L889–894)에 "**0-x IAM 신뢰/리소스 기반 정책**이 여기 API 리소스 정책의 교차 계정 조건으로 적용" 한 줄. `SecArch`(L1002–1007)에 CloudFront/S3 선행 챕터 지목.
2. **(축2 소관, 위임)** 29초 규칙(`SecMonitoring` L801–804)·스테이지 변수 전달 경로(`SecStages` L579)·REST vs HTTP 인증 행(`SecRestVsHttp` L936)·로그 레벨 ERROR/DEBUG/INFO(`SecMonitoring` L779) 사실 수정은 축2 리포트 수정지시 1~6 준수. 축1은 배치·설계만 평가하므로 값 수정은 축2 완료 시 반영.

## 보충 생성 목록 (결손 성분)

- **[퀴즈·해설 전면 결손]** L1·L2·L7·L8 N/A의 근본 원인. 파일 내 상황→정답 콜아웃이 이미 문항 소재로 완성돼 있어 전환 난이도 낮음:
  - `SecStages` "배포 안 하면 반영 안 됨"(L560–561) → "변경했는데 왜 안 바뀌죠?" 적용형 시나리오 문항.
  - `SecIntegration` "매핑 템플릿 필요=프록시 통합 불가"(L672–674) → JSON↔XML / 쿼리스트링 이름변경 지문 문항.
  - `SecAuth` "문제 풀이 공식" 3줄(L916–919) → 교차 계정 / 앱 회원 로그인 / 외부 IdP 상황별 정답 선택 문항.
  - `SecOverview` ACM 인증서 리전 함정(L547–551) → Edge=us-east-1 vs Regional=동일 리전 변별 문항.
  - `SecCache` "Require authorization 미체크 시 아무나 무효화"(L736–739) 보안 함정 문항.
  - `SecRestVsHttp` 비교표(L931–942) → "매핑 템플릿·사용 계획·캐싱 언급 시 REST" 변별 문항.
  각 문항에 **오답별 조건화 해설** 동반 생성(L2 결손 보완).
- **[커버리지 갭, 축2 위임]** 상태 코드 오버라이드(Task 1.1 — 통합 응답 매핑·GatewayResponses)·페이로드 10MB 한도(REQUEST_TOO_LARGE 413) 개념 블록 신규 생성 후 해당 문항 추가(축2 수정지시 7).

## 반복 약점 메모

- **L6 명시 지목 부재** — 코퍼스 9개 파일 연속 L6=1. 본 파일도 Lambda alias·IAM 리소스 정책·CloudFront 등 선행 통합 소재가 풍부한데 챕터 번호 지목이 전무. 생성 프롬프트에 "각 섹션 최소 1개 선행 챕터 개념을 'N-N장의 X → 여기 Y' 형태로 명시 링크" 체크리스트 강제 필요.
- **퀴즈·해설 부재의 구조적 반복** — 레거시 설명형 콘텐츠 전형(27개 중 퀴즈 2개뿐). 그러나 본 파일은 "시험 포인트/문제 풀이 공식/시험 단골 시나리오" 콜아웃 밀도가 코퍼스 최상위라 문항 전환 자산이 가장 풍부. 생성 파이프라인에서 콜아웃→문항 자동 변환 우선 대상으로 태깅 권장.
- **모드 토글 시뮬레이터**(프록시/비프록시·인증 3방식)는 능동 인출 장치이나 채점형이 아니라 L1에 못 잡힘 — 토글 후 "이 구성에서 매핑 템플릿 가능?" 자가확인 문항을 얹으면 시뮬레이터가 곧바로 채점형 인출로 승격.
