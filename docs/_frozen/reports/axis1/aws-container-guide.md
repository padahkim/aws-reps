## 수정 지시
축1 자체는 통과선(85%)을 넘어 설계 결함은 경미하다. 유일한 감점 L6를 2로 끌어올리는 단일 지시:

- **L6 위반(유일)**: `EcsTab`의 "ECS의 IAM 역할" `Sec`(L284–320) 도입부 `P`(L285) 또는 IAM 역할 카드(L307–316)에 **선행 IAM 챕터 명시 역참조** 추가. 예: "선행 IAM 챕터(커리큘럼 매핑상 1-x장)에서 배운 **역할의 신뢰 정책(AssumeRole)**이, 여기서 ECS Task Execution Role/Task Role이 각각 ECS 서비스·앱 컨테이너에게 위임되는 방식으로 그대로 적용된다" 식의 챕터·개념 동시 지목. (정확한 선행 챕터 번호는 커리큘럼 매핑표에서 확정해 삽입.) 보조로 `EcsTab` EFS 섹션(L348)·`TaskDefTab` 환경변수 섹션(L646)에도 "선행 스토리지/시크릿 관리 챕터의 EFS·Secrets Manager 개념" 명시 역참조를 달면 챕터 통합이 강화된다. 현재의 "태스크 정의 탭 참고"(L342)·"170강 참고"(L281)는 동일 챕터 내부 링크·강의 번호라 L6 근거가 되지 못함.

> 주: 축2 「높음」 오류(IAM 역할 자기모순, L307–311 vs L652)의 사실 수정은 **축2 소관**이며 종합 게이트다. L6 역참조 문구를 새로 넣을 때 축2 수정 지시 1번(이미지 pull·로그·시크릿 조회를 Task Execution Role로 이관)과 **동시에 반영**해야 모순 재발이 없다.

## 보충 생성 목록 (결손 성분)
퀴즈·해설이 전면 결손(핵심 갭). 본문에 이미 "시험 포인트/결정표" 콜아웃이 풍부해 문항 소재는 충분하다. 각 콜아웃을 채점형 문항+해설로 승격 권장:

- **IAM 역할 결정형**(소재: Tip L318–319 + Summary L895): "인스턴스가 ECR에서 이미지를 못 가져온다 / 로그가 CloudWatch에 안 올라간다" → 정답 **Task Execution Role**(축2 수정 후 기준). 오답으로 Task Role·Instance Profile 배치. **축2 「높음」 오류 수정 확정 후 생성**할 것.
- **Launch Type 매칭형**(소재: Tip L279): "서버리스·인프라 관리 없음" 지문 → Fargate vs EC2 4지선다.
- **롤링 업데이트 계산형**(소재: `RollingDemo` L378–401, Tip L497–499): "태스크 4개, min 50%/max 100%일 때 동시 존재 가능 최소/최대 개수" 수치 계산 문항 — 데모가 정답 근거 시각화를 이미 제공.
- **태스크 배치 키워드형**(소재: Tip L779–780): 비용 최소화=binpack / 고가용성=spread(AZ) / 전부 다른 인스턴스=distinctInstance / 특정 타입만=memberOf.
- **스토리지 함정형**(소재: Tip L371–372, 함정 모음 L933·937): "멀티 AZ 영속 공유 스토리지" → EFS(S3 마운트 불가 오답 유도), "EKS+Fargate 볼륨" → EFS 단일.
- **오토 스케일링 지표형**: 축2 수정 지시 3번(딱 3가지 → "대표 3종 + 커스텀 CloudWatch 지표 가능") 반영 후 문항화 — 그 전 생성 시 오답 확정 위험.

**커버리지 갭(축2 위임)**: 헬스체크·레디니스 프로브(축2 Task 4.2.8 "부분 갭") 미커버 — 콘텐츠 보강은 축2 소관. 보강되면 "ALB 대상 그룹 헬스체크 vs 컨테이너 healthCheck 필드" 구분 문항 추가 권장. Copilot EOS(2026-06-12) 반영(축2 수정 지시 2번)도 문항화 전 선행.

## 반복 약점 메모
- **L6 명시 지목 부재 = 코퍼스 공통 패턴 9연속.** 지금까지 8개 파일 전부 L6=1, 이 파일도 1. 원인 동일: 콘텐츠가 자기 챕터 내부 완결성에는 충실하나 **선행 챕터를 개념·번호로 콕 집어 재활용**하는 문장이 없음. 서비스 이름 배경 언급·"~탭 참고"·강의 번호는 L6 근거 불가. 생성 프롬프트에 "IAM/네트워킹/스토리지 등 선행 챕터 개념이 재등장하는 지점마다 'N-N장의 X 개념이 여기 Y로 적용' 형식 역참조를 최소 1회 명시하라"를 상수로 넣을 것을 재차 권고.

## 스키마 피드백 요약
- 축2가 이미 기록한 항목과 동일 관찰(신규 없음): 상태 기반 단계 시각화 데모(`RollingDemo`·`PlacementDemo`)와 빈출도 정렬 총정리표(`SummaryTab`)는 스키마 v0 미표현 구조. 축1 관점에서 두 데모는 **채점형 문항으로 승격 가능한 인출 장치**라는 점을 부기 — 스키마에 "인터랙티브 데모 → 대응 문항 자동 연결" 필드가 있으면 결손 퀴즈 생성이 직결된다.
