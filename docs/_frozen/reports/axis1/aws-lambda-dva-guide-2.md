## 수정 지시

축1 판정 통과 — 축1 필수 수정 없음. 종합 판정 게이트는 **축2 콜드 스타트 "최대 10초" 근거 미확인**(Tab2 SVG 라인 435 주석)이며 이는 축2 소관.

1. **[L3 상향 여지, 이미 2 — 완성도 개선]** 각 개념 블록에 실전 코드형 예시를 개념-직후 1개씩 병기하면 코드 판독형 지문 대비를 보강. 예: `TabConcurrency` Reserved 슬라이더 밑에 `aws lambda put-function-concurrency --reserved-concurrent-executions 200` CLI 1줄, `TabSecurity` 권한 카드 옆에 리소스 기반 정책 JSON 골격 1개(`lambda:InvokeFunction` + S3 Principal), `TabDeploy`에 별칭 라우팅 설정 스니펫 1개. (필수 아님 — L3 이미 2)
2. **[L6 상향, 1→2 (선택·설계 개선)]** 선행 챕터 명시 지목으로만 2 획득. 구체 지점:
   - `TabSecurity` 권한 카드(라인 1339~1347, 실행 역할/리소스 정책) → "0-2장 IAM 신뢰 정책이 Lambda 실행 역할의 `sts:AssumeRole` 대상으로 적용" 지목 문장 추가.
   - `TabSecurity` 모니터링 카드(라인 1443, KMS 환경 변수 암호화) → "3-2 KMS 챕터의 봉투 암호화가 여기 환경 변수 암호화에 적용" 브리지.
   - `TabInvocation` 폴링 ESM(라인 799~813, SQS/Kinesis) → "2-1 메시징 챕터의 SQS 가시성 타임아웃·Kinesis 샤드 개념이 ESM 배치 처리의 전제" 역참조.

## 보충 생성 목록 (결손 성분)

- **[퀴즈·해설 전면 결손]** L1·L2·L7·L8 N/A의 원인. 이 파일은 **문항 전환 소재가 이미 풍부** — 별도 창작 없이 승격 가능:
  - `TabExam` "시나리오→정답 패턴" 9개(라인 1544~1596: 콜드스타트→Provisioned, 폭주 격리→Reserved, 비동기 실패→Destinations, S3 미호출→리소스 정책, VPC 인터넷→NAT, 샤드 블로킹→Bisect, 점진 배포→가중치 별칭+CodeDeploy, DB 연결→핸들러 밖/RDS Proxy, 시크릿→Secrets Manager) → **9개 그대로 4지선다 문항화**. 오답 씨앗: 인접 개념 혼동(Reserved↔Provisioned, DLQ↔Destinations, 리소스 정책↔실행 역할).
  - 동시성 슬라이더(`TabConcurrency`) → "함수 A에 200 예약 시 나머지 함수 공유 풀은?" 조작 결과 확인 단답 문항.
  - `TabInvocation` 세 방식 비교표(라인 848~867) → "재시도/에러 처리/응답" 열을 True/False 자가채점으로 전환.
  - 각 문항에 **오답 조건화 해설**(예: "429는 동기 스로틀 — 비동기는 6시간 재시도라 429 아님") 병기해 L2 결손 동시 보강.
- **[커버리지 — 축2 소관]** 축2 「누락」: Lambda 익스텐션(Extensions API)·단위 테스트/SAM 로컬 테스트·컨테이너 이미지 배포·Firehose 준실시간 변환 개념 블록 신설, Kinesis/DDB Streams ESM 오류 처리(병렬화 계수·bisect) 세부 보강 → 축2 수정 지시 3번 소관. **VPC 프라이빗 리소스 접근은 본 파일이 이미 커버**(`TabSecurity` VPC 카드, 라인 1355~1434, ENI/RDS 프라이빗/NAT/`AWSLambdaVPCAccessExecutionRole`) — 형제 파일(lambda-dva-guide, lambda-dva-study)의 VPC 누락과 대조되는 강점. 신규 블록 생성 시 위 L3(개념-직후 시뮬레이터/코드)·L6(선행 챕터 지목) 패턴 동시 적용 권고.

## 반복 약점 메모

- **퀴즈·해설 부재 → L1·L2·L7·L8 N/A**: 코퍼스 공통(퀴즈 미보유 파일 전원 동일 — s3-guide·본 파일 등). 보충 생성 목록이 최대 산출물이나, **본 파일은 시뮬레이터·시나리오 리스트라는 우수한 문항 씨앗을 보유** → 전환 비용 최저 그룹.
- **코드/CLI/JSON 부재(L3)**: 인터랙티브 시뮬레이터·도식·클릭 비교는 강하나 실행 코드 전무 → 코드 판독형 지문 대비 약함. lambda-dva-study·messaging·template과 공통 약점. 단 본 파일은 **슬라이더·클릭 능동 조작**으로 L3를 2까지 끌어올려, 코드 부재를 인터랙션으로 부분 상쇄한 사례(대비: lambda-dva-study는 시뮬레이터 크레딧이 L1로 흡수돼 L3=1).
- **L6 선행 브리지 부재**: 명시 "N-N장" 역참조 없어 L6=1 고착 — **코퍼스 전역 최다 반복 감점(지금까지 전 파일 L6=1)**. 관련 서비스 배경 언급은 우수하나 챕터 간 브리지 없음. 생성 프롬프트에 "선행 챕터 id 명시 역참조 1개 이상 삽입" 규칙 격상 확정 권장.

## 스키마 피드백 요약

- 축2가 제안한 `interactiveSlider[]{param, min, max, effect}`(동시성 분배·가중치 트래픽 조작)·`decisionTable[]{scenario, choice, why?}`(시나리오→정답 패턴)의 **근거 사례로 본 파일 재확인** — 신규 필드 아님. 두 구조 모두 v0 미대응이며, `interactiveSlider`는 능동 인출(L3 강화) 장치, `decisionTable`은 L1 문항 자동 승격 파이프라인 입력으로 직결(과제: 리스트 9개 → 4지선다). 
- 신규 관찰: `Hint`("DVA 시험 포인트" + "함정" 표기)가 정답 근거·오답 함정을 이미 텍스트로 보유 → 스키마 v1에 `examTrap{point, trap}` 필드를 두면 문항 오답 해설(L2)로 자동 전환 가능(제안, 직접 수정 안 함). 탭 네비게이션(`tabs[]`) 구조는 파일1의 sidebar+scroll과 다른 패턴 — B계열 별도 기록 대상.
