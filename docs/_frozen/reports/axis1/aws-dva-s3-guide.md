# 축1 리포트: aws-dva-s3-guide

**모드**: 레거시 / **평가 범위**: 부분 평가 (N/A: L1·L2·L7·L8 — 퀴즈 성분 없음) / **판정: 통과** (유효 총점 7/8 = 87.5%)

> 축2 판정: 수정(객체 최대 5TB→50TB 3곳·KMS 초당 한도 5,500~30,000 확인불가·"버킷 정책은 기본 암호화보다 먼저 평가" 순서 단정 확인불가). **두 축 종합 = 수정.** 축2 오류는 전부 수치·시간차 최신화·순서 단정으로 학습 **설계** 결함은 아니나, 5TB·평가순서는 시험 포인트 콜아웃에 박혀 있어 사실 수정 전 학습 시 오개념 고착 위험 → 축2 수정 우선.
> 성분 태그(축2): 설명 O · 예시 O(SVG 도식 17개·시나리오·정책/헤더 값 — CLI/JSON 실코드 없음) · 퀴즈 X · 해설 X / 매핑: 1-1 S3. (중복 쌍: aws-s3-dva-guide — 이 파일은 SVG 도식 위주·실코드 없음)

## 수정 지시

축1 판정 통과 — 축1 필수 수정 없음. **종합 게이트는 축2 수치 수정**(5TB→50TB 3곳 · KMS 한도 문구 재표현 2곳 · 평가 순서 단정 재표현 2곳). 이 값들이 `overview` Exam("5TB/5GB/멀티파트 수치")·`encryption` KP·표에 박혀 있어 학습 설계상 "시험 포인트로 콕 집은" 위치라 오개념 고착 위험이 가장 큼 → 사실 수정을 종합 통과의 선결로 명기.

1. **[L6 상향 여지, 1→2]** 학습 설계 개선안(선택): `security` 버킷 정책 섹션에서 "(IAM 허용 OR 리소스 정책 허용) AND 명시적 Deny 없음" 지점에 "IAM 챕터의 정책 평가 로직(Deny 우선)과 동일 규칙" 식 **선행 커리큘럼 챕터 명시 지목** 추가. `replication`의 "버전 관리 필수"에 versioning 섹션 번호(강의 121) 역참조를 명시하면 자기 가이드 내 spaced-retrieval 강화. (현 상태로도 통과 — 강행 아님)
2. **[구조 미세조정, L3 견고화]** `Exam` 콜아웃이 섹션 말단에 일괄 배치됨 — 각 KP 직후로 인터리브하거나, 최빈출 섹션(performance·encryption·presigned freq5)만이라도 개념 카드 바로 아래로 당기면 인출 근접성↑. (감점 요인 아님, 완성도 제안)

## 보충 생성 목록 (결손 성분)

- **[퀴즈·해설 결손 — 최우선 산출물]** L1·L2·L7·L8 N/A의 원인. 변환 단계에서 채점형 문항+오답 조건화 해설 신규 생성 필요. **전환 소재 이미 풍부**: `Exam` 콜아웃 17개가 대부분 "상황→정답 서비스" 실전 지문형이라 4지선다 문항으로 직접 전환 가능(전환 난이도 최저). 특히 freq5 섹션(performance·encryption·presigned)과 함정 선지("태그로 검색 불가→DynamoDB", "로깅 버킷=대상 버킷 무한루프", "CORS는 요청받는 버킷 B에", "복제 체이닝 불가")를 문항화.
- **[해설 씨앗]** 각 `Exam`의 "왜 이 답인가"는 KP·`Warn` 블록에 분산 존재 → 오답별 조건화 해설로 재조립하면 L2 확보.
- **[커버리지 — 축2 소관]** 축2 「누락: 없음」 — 1-1 범위 커버리지는 완전. 중복 쌍(aws-s3-dva-guide)이 버킷 정책 JSON 실코드·S3 Bucket Key 해결책 보유 → 통합 시 이 파일의 SVG 도식 + 상대 파일의 실코드 결합이 L3를 "명확한 2"로 끌어올림(통합 결정은 인간 몫).

## 반복 약점 메모

- **퀴즈·해설 부재** → L1·L2·L7·L8 N/A. 코퍼스 공통(퀴즈 보유 파일 27개 중 2개뿐). 이 파일도 동일 패턴.
- **L6 = 1 고착**: "146강 참고" 같은 **동일 가이드 내부** 상호링크·서비스 이름 배경 언급은 있으나 **선행 커리큘럼 챕터 명시 지목** 부재. 코퍼스 전역 최다 반복 감점(배치1·2 전원 L6=1)에 이 파일도 합류.
- **`Exam` 말단 일괄 배치**: 시나리오 콜아웃이 섹션 끝에 몰리는 구조는 messaging·본 파일 공통 — L3는 2를 유지하나(헤더값·표 인접성 덕), 인터리빙 여지 상존.
- **빈출도 태그(`FreqBadge`/`freq`) 재현**: 배치 전반의 최강 재현 스키마 요소(B7) 계속 누적.

## 스키마 피드백 요약

- **B7(빈출도 태그) 재현**: `FreqBadge` 5→2단계 + 사이드바 `●` 도트. 기존 제안과 동일 패턴이라 중복 기록 생략.
- **신규 관찰 — `GROUP_QUIZ` 외부 퀴즈 매핑**: `{그룹 → "퀴즈 8/10/11"}` 구조로 콘텐츠 그룹을 외부 문제은행 범위에 연결. 축2 리포트도 동일 구조를 `SCHEMA_FEEDBACK_AXIS2`에 기록함. 축1 관점 보강: 이 매핑이 존재하면 **문항 생성 파이프라인이 "어느 섹션이 어느 퀴즈에 귀속되는지"를 입력받아** L8(누적 복습) 문항을 그룹 경계에서 자동 배치 가능 → 스키마 v1에 `quizGroup` 필드 제안(직접 수정 안 함).
- **콜아웃 3유형(`KP`/`Warn`/`Exam`)**: dynamodb-guide 행과 동일 패턴이라 중복 기록 생략. `Exam`은 L1 문항의 직접 씨앗이 되므로 스키마에서 별도 태깅 가치.
