**모드**: 레거시 / **평가 범위**: 부분 평가 (N/A: L1·L2·L7·L8 — 퀴즈 성분 없음) / **판정: 통과** (유효 총점 7/8 = 87.5%)

## 수정 지시

축1 판정 통과 — 축1 필수 수정 없음. **종합 게이트는 축2 명칭·수치·커버리지 수정**(6종→5종+Blue/Green 별도 표기, 버전 1,000개=리전 합산 쿼터, 헬스체크·플랫폼 브랜치 보강). 특히 "6종" 표기는 `SECTIONS`/`FREQ`("배포 정책 6종 — 요구조건 매칭", 598)·`SecDeploy` 소제목(1857)·정답공식 note(1923)에 **시험 포인트로 콕 집은 위치**에 반복 노출돼 오개념 고착 위험이 가장 큼 → 사실 수정을 종합 통과의 선결로 명기(교정 자체는 축2 소관 위임).

1. **[L6 상향 여지, 1→2]** 학습 설계 개선안(선택): `SecOverview` "새로운 기술이 아니다 — EC2, ASG, ELB, RDS…"(1757) 및 `ProblemSolution` "익숙한 EC2·ASG·ELB·RDS"(1205) 지점에 **선행 커리큘럼 챕터 명시 지목**(예: "N-N장 EC2·N-N장 ASG·N-N장 ELB에서 개별로 배운 서비스를 EB가 하나로 묶는다") 추가. `TierDiagram`의 SQS 워커 티어(1373)에는 SQS 챕터 역참조, `CfnDiagram`(1584)에는 CloudFormation 챕터 역참조를 달면 spaced-retrieval 강화. (현 상태로도 통과 — 강행 아님)
2. **[구조 미세조정, L3 견고화]** `KEYWORDS` "지문→정답" 그리드(2184)와 "정답 고르는 공식" note(1923)가 총정리 탭 말단에 몰려 있음 — 최빈출 `SecDeploy`(freq5) 시뮬레이터 직후로 카나리·즉시롤백 등 핵심 큐 카드 2~3개를 미리 당기면 인출 근접성↑. (감점 요인 아님, 완성도 제안)

## 보충 생성 목록 (결손 성분)

- **[퀴즈·해설 결손 — 최우선 산출물]** L1·L2·L7·L8 N/A의 원인. 변환 단계에서 채점형 문항+오답 조건화 해설 신규 생성 필요. **전환 소재 이미 풍부**:
  - `KEYWORDS` 12장(644) — 대부분 "조건 지문 → 정책/절차 정답"이라 4지선다로 직접 전환(전환 난이도 최저). 함정 선지는 표 대조축에서 조달: "무중단인데 추가 비용 0 → Rolling(오답: Rolling+batch는 소폭 비용)", "즉시 롤백 필요 → Immutable(오답: Rolling은 느린 재배포)", "DNS 변경 힌트 → Blue/Green만".
  - `FREQ` 9주제(596)·"정답 고르는 공식"(1923)의 조건 분기(다운타임 허용?→All at once 등) → 조건 매칭 시나리오 문항.
  - `RdsSteps` 6단계(1672) → 순서 배열/누락 단계 찾기 문항("삭제 방지를 건너뛰면?"). `LbMigration`(1655) "복제 불가 이유" → 함정 문항.
  - `MEMO` 8줄(680)·`COMPARE` 표(532) → 참/거짓·표 셀 빈칸 채우기.
  - `Simulator` 스텝 캡션(예 Immutable "임시 ASG만 종료하면 즉시 롤백", 390) → "이 단계의 가용 용량은?"·"실패 시 롤백 비용은?" 상태 판독 문항.
- **[해설 씨앗]** 각 정책 `points` 불릿·스펙 스트립(롤백/추가비용/추천)·`note`/`warnbox` 블록에 "왜 이 답인가"가 분산 존재 → 오답별 조건화 해설로 재조립하면 L2 확보.
- **[커버리지 — 축2 소관 위임]** 축2 「누락」: (a) 헬스 체크 — Basic vs Enhanced Health Reporting·헬스 상태 5단계(Ok/Info/Warning/Degraded/Severe)와 Immutable·Traffic splitting의 "헬스 체크 통과" 판정 기준 연결(시뮬레이터가 "헬스 체크 통과" 문구를 여러 번 쓰면서 본문 정의 부재), (b) 플랫폼 브랜치·버전·관리형 플랫폼 업데이트. 두 항목은 문항 생성 전 콘텐츠 보강이 선행돼야 함(축2 커버리지 소관).

## 반복 약점 메모

- **퀴즈·해설 부재** → L1·L2·L7·L8 N/A. 코퍼스 공통(퀴즈 보유 파일 소수). 이 파일도 동일 패턴 — 단, 지문형 `KEYWORDS`·조건분기 공식이 있어 문항 전환 난이도는 코퍼스 최저군.
- **L6 = 1 고착**: EC2·ASG·ELB·RDS·CFN·SQS·Route 53를 "익숙한/기존" 식 서비스 이름 배경으로만 언급, **선행 커리큘럼 챕터 명시 역참조 부재**. 코퍼스 전역 최다 반복 감점(지금까지 9개 파일 전원 L6=1)에 합류. EB는 다수 선행 서비스를 통합하는 챕터라 명시 역참조 여지가 오히려 큼 → 생성 프롬프트에 "통합형 챕터는 구성 서비스별 선행 챕터 번호를 명시 지목" 룰 추가 권고.
- **상황→정답 콜아웃 말단 집중**: `KEYWORDS`·정답공식이 총정리 탭에 몰림 — S3·messaging과 동일 패턴. L3는 시뮬레이터·실코드 인접성으로 2 유지하나 인터리빙 여지 상존.

## 스키마 피드백 요약

- **신규 관찰 — 다변형 스텝 재생 시뮬레이터**: `Simulator`(922) + `MODES[]`(181)가 "동일 개념(배포)을 6개 변형(모드)으로 전환 × 각 변형마다 다단계 시퀀스(steps[]) 재생 + 용량 게이지/트래픽 분할 바" 조합. 축2도 `SCHEMA_FEEDBACK_AXIS2.md`에 별도 근거로 기록. 축1 관점 보강: 이 구조는 **각 스텝 캡션·용량 값이 곧 L1 상태판독 문항의 씨앗**이므로, 스키마에 `simulator{modes[]{steps[]{caption, capacity, ...}}}` + 스텝별 `assertable` 태그를 두면 문항 자동 파생 가능(직접 수정 안 함).
- **빈출도 태그(`Stars`/`freq`) 재현**: 탭·`SectionHead`·`FREQ` 3중 노출. 배치 전반 최강 재현 스키마 요소 — 중복 기록 생략.
- **`KEYWORDS` 키워드 매칭 그리드**: 기존 `decisionTable[]{scenario, choice, why?}` 제안과 동일 계열(축2도 동일 판단). `why` 필드가 비어 있어 해설 씨앗은 `points`/스펙에서 조달해야 함 — 스키마에 큐 카드별 `rationale` 필드 추가 시 L2 직접 파생.
