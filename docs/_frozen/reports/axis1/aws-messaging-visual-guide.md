## 수정 지시
축1 설계 결함은 만점(85%↑)이라 필수 수정은 없음. 통과선을 넘긴 상태이나 L6 1점 만회를 원하면:

- **L6 상향(1→2, 선택)**: 현재 역참조는 전부 파일 내부 링크뿐이다. **선행 챕터를 명시 지목**하는 한 줄을 삽입하라.
  - s220 SQS 액세스 정책 서두(1492–1495): "S3 버킷 정책과 비슷한" → "**앞 S3 챕터의 버킷 리소스 정책(Principal/Action/Resource 구조)** 을 그대로 큐에 적용한 것"처럼 특정 선행 챕터·개념을 지목.
  - s220 IAM 대비 서술(1494–1495 "IAM 정책(주체 기준)과 달리"): "**IAM 챕터에서 배운 주체 기반 정책**과 달리 리소스 쪽에서 허용" 식으로 선행 챕터를 명시 역참조.
  - 이때 근거로 실제 앞 챕터 번호/제목을 인용해야 2점 인정(코퍼스 기준: 서비스명·"~와 유사"·내부 링크는 1 유지).

## 보충 생성 목록 (결손 성분)
퀴즈·해설이 전면 결손(L1·L2·L7·L8 N/A)이다. 아래 콜아웃/표를 문항 소재로 삼아 MCQ+해설을 생성하라(파일 자체 수정은 축1 소관 아님 — 생성 위임 목록):

- **s221 가시성 타임아웃** Exam/Warn(1569–1579): "메시지가 두 번 처리된다" 시나리오 → 원인(타임아웃 < 처리시간)·정답 API(`ChangeMessageVisibility`) 4지선다 + 기본 30초/최소 0초/최대 12시간 수치 확인 문항.
- **s222 DLQ** Exam(1626–1629): "반복 실패 메시지 격리/디버깅" → `DLQ + maxReceiveCount`, 재처리 → `redrive`; FIFO큐 DLQ는 FIFO여야 함 오답 함정.
- **s225 개발자 개념** Exam(1732–1735): "빈 수신 多·API 비용↑" → 롱 폴링 / "본문 256KB 초과" → SQS 확장 클라이언트+S3 오프로딩 분기 문항.
- **s226 FIFO** Warn/Exam(1774–1783): "순서 보장+중복 불가" → FIFO vs "초고속 대량+순서 무관" → 표준 선택; 300/3,000 msg/s·`.fifo` 접미사·전환 불가 수치 문항.
- **s229 팬아웃** Warn(1947–1952): "팬아웃이 동작 안 함" → SQS 큐 정책이 SNS 쓰기 미허용(대표 오답 원인) 진단 문항; "S3 이벤트를 여러 대상에" → S3→SNS→다수 SQS.
- **s231 Kinesis** Warn(2015–2019): 샤드 한도 초과 → `ProvisionedThroughputExceeded` → 샤드 추가/온디맨드 대응 문항.
- **s235 Flink** Warn(2111–2115): "Flink 소스" 함정 — Data Streams/MSK O, **Firehose X** 오답 선택지 문항.
- **s236 종합 비교표**(2140–2164) + 지문 신호 리스트(2166–2179): 지문 한 줄→SQS/SNS/Kinesis 판별 결정형 문항(코퍼스 최상위 빈출 소재).
- **[축2 위임] 커버리지 갭**: KCL(Kinesis Client Library)·KPL(Kinesis Producer Library) 용어 전무 — 축2 리포트 「수정 지시 1」에 보강 지시 있음. 축2 소관으로 위임(축1 채점엔 영향 없음: 설계 결함 아니라 콘텐츠 커버리지 누락).

## 반복 약점 메모
- **L6 명시 선행-챕터 지목 부재** — 코퍼스 9번째 연속 L6=1. 이 파일도 내부 모듈 교차링크(→221/→229/→220)는 촘촘하나 **선행 챕터 통합 역참조가 0건**. 생성 프롬프트에 "S3/IAM 등 앞 챕터 개념을 'N-N장에서 배운 X를 여기서 Y로 적용' 형식으로 최소 1회 명시 지목" 지시를 추가하면 코퍼스 공통 감점을 해소 가능.
- 강점(유지): 개념 직후 CLI/JSON 실코드 인접(L3=2) + 개념 원자화·수치 Stat 카드(L4=2)는 상대 중복 파일(aws-dva-messaging.jsx, 코드 스니펫 전무) 대비 이 파일의 우위. 중복 쌍 정리 시 이 파일이 L3·L4 설계 기준선.

## 스키마 피드백 요약
- **빈출도(freq) 3단 태그**(`FREQ` 3/2/1 → Bars 시각화, 각 섹션 `freq` 필드)가 v0 스키마에 미표현. 인출 우선순위·간격반복 스케줄링 신호로 활용 가치 있어 스키마 필드화 권장.
- **콜아웃 3분류 택소노미**(⚑시험 포인트=지문신호→정답 / ⚠함정 주의=오답 선택지 / ◈참고=보조)가 문항 생성 소재로 직결 — 스키마에 콜아웃 kind별 "문항 시드" 태그를 두면 L1 보충 생성이 자동화 가능.
- **결정표(비교 Tbl)+결정 트리 다이어그램(D_Compare)** 의 "지문 신호→서비스" 매핑 구조가 반복 등장 — 이 구조를 스키마 "decision-table" 유형으로 명시하면 종합 비교 토픽(코퍼스 공통 최빈출) 표준화에 유용.
