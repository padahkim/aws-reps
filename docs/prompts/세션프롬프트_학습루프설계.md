# 학습 루프 설계 프롬프트 — 오답 재출제·숙달 판정·진도 계산 (스프린트 후속 대기 카드)

> **저장 위치**: `docs/prompts/학습루프설계.md`
> **실행 조건**: **규약사전분석 스프린트가 끝난 뒤, 같은 세션에서 이어서(또는 새 세션) 순차 실행.** 스프린트와 병렬 실행 금지 — Fable 한도를 나눠 쓰면 둘 다 잘린다.
> **모델**: Fable + `/effort high` (학습과학 + 알고리즘 설계 = 지능 병목 작업). 시간이 애매하면 Sonnet으로도 무방 — 그 경우 산출물을 나중에 Fable 체크인에서 한 번 검토.
> **왜 지금 가능한가**: 이 설계는 규약 상세에 얕게만 의존한다 — "문항에 id·정답·해설이 있다"는 가정이면 충분해서, 규약 v1 확정 전에 만들어도 재작업이 거의 없다.

## 프롬프트 본문 (아래부터 복사)

너는 **학습 루프 설계자**다. 이 프로젝트(DVA-C02 학습 웹앱)의 콘텐츠 품질은 평가 파이프라인이 잡고 있지만, **앱의 학습 동작** — 틀린 문제를 언제 다시 물을지, 무엇을 근거로 "이 챕터는 완료"라고 판정할지 — 은 아직 설계가 없다. 이것을 `docs/LEARNING_LOOP_DRAFT.md` 한 문서로 설계하라. 산출물은 이후 앱 트랙(핸드오프 세션)의 입력이 된다.

### 0. 준비
- 정독: `docs/CURRICULUM.md` §1·§4(앱 요구사항 — 퀴즈 엔진·오답 노트·진도), `docs/RUBRIC.md` §8의 학습과학 원리(특히 L8 간격 반복의 취지), `BOARD.md`
- `docs/CONTRACT_PREWORK.md`가 있으면 §2의 quiz 필드 설계 권고를 참조하라 (id 규칙·concept 태그)
- BOARD 단계 4 표 아래에 자기 행 추가: `| 4-0a | 학습 루프 설계 | 설계 세션 | 진행 | docs/LEARNING_LOOP_DRAFT.md | 앱 트랙 입력 |` + 로그 append. 섹션 완성 즉시 저장·커밋(몰아서 저장 금지)

### 1. 설계할 것 (우선순위 순)

**① 오답 재출제 정책 (간격 반복)** — 틀린 문항을 언제 다시 보여줄 것인가:
- 후보 비교: 고정 간격(예: 1일/3일/7일) vs Leitner 상자식(맞히면 승급, 틀리면 1단계로) vs SM-2 계열 — **1인 프로젝트의 구현 난도와 효과의 균형**으로 선택하고 근거를 달아라. 과설계 금지: MVP는 상자 3~4개 수준을 넘지 마라
- "다시 풀 시간이 됐다"를 사용자에게 어떻게 노출할지 (오답 노트 진입 시 due 문항 우선 정렬 등)
- 정답 처리의 정의: 재출제에서 맞히면 승급, 선택지 순서 셔플 여부

**② 숙달 판정 기준** — 무엇을 "완료"로 치는가:
- 문항 단위: 연속 정답 n회? 마지막 시도 기준? — 기준과 근거
- 개념 단위: `concept` 태그별 정답률로 약점 개념 산출 (태그가 없는 레거시 문항의 폴백 포함)
- 챕터 단위: 섹션 열람 + finalQuiz 점수 조합 — "완료" 배지의 정확한 조건식
- 망각 반영: 완료 챕터도 오답 이력이 있으면 due 문항이 다시 뜨는가?

**③ 진도·커버리지 계산식**:
- 전체 진행률(챕터 가중: 도메인 비중 반영 여부 결정), 도메인별 커버리지의 정확한 산식
- 대시보드에 보여줄 최소 지표 3개 이내 선정 (지표 과잉 금지)

**④ 데이터 구조 초안 (localStorage)**:
- 위 ①~③을 지탱하는 키 구조와 레코드 형태 (예: `attempts`, `boxState`, `chapterProgress`)
- **규약 의존 최소화 원칙**: 문항 참조는 Question id로만. 규약 v1에서 필드가 바뀌어도 이 설계가 살아남도록 의존 지점을 명시적으로 표기하라
- 마이그레이션 고려: 구조 버전 필드 하나 포함

### 2. 완료 절차
LEARNING_LOOP_DRAFT.md 커밋 → BOARD 4-0a를 `정지-승인대기`로, 승인 대기함에 "학습 루프 초안 검토 — 결정 필요 항목 N건" 등록 → 종료. 인간이 골라야 할 결정(재출제 방식 등)은 §마다 "선택지 + 권고"로 남겨라 — 확정 어조 금지.

### 금지 사항
- 코드 구현 금지 — 설계 문서만. 구현은 앱 트랙(핸드오프)의 일이다
- /content·RUBRIC·CURRICULUM·PLAYBOOK 수정 금지
- 쓰기 허용: `docs/LEARNING_LOOP_DRAFT.md`와 BOARD 자기 행·로그만
- 과설계 경보: 알고리즘 설명이 2페이지를 넘거나 상태가 5종을 넘으면 스스로 단순화하라 — 이 앱의 사용자는 시험 준비생 1명이다
