# 세션 프롬프트 — 프로젝트 구조 이해 문서 작성 (`docs/ARCHITECTURE.md`)

> **사용법**: 리포 루트에서 새 세션을 열고 플랜 모드(Shift+Tab 두 번)로 아래 "본문"을 투입한다.
> **산출물**: 처음 보는 사람도 이 프로젝트를 빠르게 이해하는 살아있는 문서 1개 — `docs/ARCHITECTURE.md` (한국어, mermaid 다이어그램 포함).
> **독자**: ① 나중의 나(회상용) ② 새 기여자(로컬 실행·구조 파악) ③ 공개 독자(프로젝트 소개). 진단 리포트가 아니라 "이게 뭐고 어떻게 굴러가나"를 설명하는 **안내서**다.
> **착지 위치**: 이 프롬프트 파일 = `docs/prompts/아키텍처안내.md` (자매 `아키텍처점검.md`와 짝: 안내 ↔ 점검). 산출물 = `docs/ARCHITECTURE.md`.
> **지위**: 재사용 후보. 한 번 돌려 유용하면 `.claude/skills/architecture-doc/`로 승격한다 — 그때 §0 정독 목록·§2 산출물 골격·부록 A(스냅샷 형식)는 그대로 두고, "코드에서 재확인 강제" 구조(작업 원칙)를 유지하면 낡지 않는다.

## 관계 — 이 문서 vs 다른 문서 (혼동 방지)

역할이 확정돼 있다. 조건부가 아니다.

- **이 프롬프트(`아키텍처안내.md`)** = 이해/온보딩용 **설명서**. `docs/ARCHITECTURE.md`(현행을 쉽게 설명하는 살아있는 문서)의 **정본 소유자**.
- **`docs/prompts/아키텍처점검.md`** = **진단/건강검진**(부채·리스크·1~5 루브릭·추세). 산출물은 `docs/ARCHITECTURE.md`가 **아니라** `docs/ARCHITECTURE_REVIEW.md`다. 점검은 이 안내서를 as-built 기준선으로 삼아 현실과 대조·채점하고, 그 결과만 REVIEW 파일에 쌓는다. (두 프롬프트가 같은 파일을 덮어쓰지 않도록 이렇게 갈라 둔다.)
- **`docs/APP_ARCHITECTURE_DRAFT.md`** = **설계 *제안* 초안 — 구현물 아님.** 이 초안이 상정한 구조 상당수가 실제로는 구현되지 않았다(부록 A의 "제안 vs 현행" 함정 참조). 대체하지 말고, 링크로 "제안은 이랬고 실제는 이렇다"만 남긴다.

## 본문 (아래부터 복사)

너는 이 세션에서 **온보딩 문서 작성 담당**이다. 프로젝트 `aws-reps`는 Next.js 정적 사이트(SSG)로 만드는 AWS DVA-C02 자격증 학습 앱이다. 임무는 하나: **처음 보는 사람이 ~15분 안에 "이 프로젝트가 뭐고, 어디에 뭐가 있고, 어떻게 굴러가고, 어떻게 기여하나"를 이해하도록** `docs/ARCHITECTURE.md`를 쓴다.

### 작업 원칙 (먼저 읽어라)
- **읽기 전용이 먼저다.** 문서를 다 쓰기 전까지 앱·콘텐츠 코드를 수정하지 마라. 이건 문서화 작업이지 리팩터링이 아니다.
- **이 프롬프트를 믿지 말고 코드에서 확인하라.** 부록 A의 스냅샷은 특정 날짜 기준이라 낡을 수 있다 — 경로·파일 수·버전·데이터 모델은 실제 파일이 정본. 부록 A와 실제가 어긋나면 실제를 따르고, 낡은 스냅샷은 이 프롬프트 개선 후보로 한 줄 남겨라.
- **이해가 목적이다 — 진단이 아니다.** 점수·심각도별 부채 목록·버그 사냥은 자매 프롬프트(`아키텍처점검.md`)의 몫. 지나가다 진짜 결함이 보이면 문서 말미 "알아두면 좋은 점" 한 줄이나 `/write-issue`로만 남기고, 본문을 진단문으로 만들지 마라.
- **쉬운 말로, 이유까지.** 약어는 처음 나올 때 풀어 쓴다(SSG=정적 사이트 생성, MDX=Markdown+JSX 등). "무엇"뿐 아니라 "왜 이렇게 했나"를 한 줄씩. 코드 참조는 이해에 도움될 때만 `파일:라인` — 문장마다 붙일 필요 없다.

### 0. 기준 정독
- `CLAUDE.md` — 프로젝트 목적·브랜치 전략·과제 관리·프로세스 규칙. (§2.8 기여 흐름의 1차 출처)
- `content/schema.ts` — 챕터 모듈 계약의 **단일 진실(규약 v3, CONFIRMED)**. 주석이 설계 이유·결정·위반 증상까지 담고 있어 콘텐츠 파이프라인 이해의 핵심. **현행 정본은 여기다.**
- `docs/CURRICULUM.md` — 커리큘럼/콘텐츠 계획(24챕터 트리·시험 도메인 가중치)의 정본.
- `docs/APP_ARCHITECTURE_DRAFT.md` — 설계 *제안* 초안(현행 아님). 맥락 참고용 — 부록 A "제안 vs 현행" 함정을 먼저 읽고 대조하라.
- `package.json` — 스택·스크립트 체인.

### 1. 훑기 — 뭐가 어디 있나 (읽기 전용 스캔)
실제 트리를 보고 아래를 파악하라. (부록 A에 검증된 출발점이 있지만, 진짜 구조는 코드에서 재확인.)
- **스택·실행·배포**: `package.json` 스크립트(predev·dev·validate·prebuild·build·typecheck), `next.config.ts`의 `output: "export"`(서버 없는 순수 SSG)와 그 의미, MDX 설정(remark/rehype 플러그인 금지), `tsconfig.json`, `.github/workflows/ci.yml`(무엇을 검사/무엇을 안 하나), `.claude/launch.json`(dev 실행법), Vercel(develop→프리뷰 / main→프로덕션, aws-reps.vercel.app; 리포에 vercel.json 없음=대시보드 설정).
- **라우팅·화면**: `app/` 트리 — 홈(`page.tsx`), 챕터 목차(`chapters/[id]/page.tsx`), **실제 읽기 페이지**(`chapters/[id]/[sec]/page.tsx`), 원본 검수 도구(`_source/`, dev/프리뷰 전용). `generateStaticParams`+`dynamicParams=false`가 만드는 SSG 경계, 서버 컴포넌트 vs `"use client"` 구분, `loadBody` 동적 import(챕터별 코드 분리 — **섹션 단위** 렌더러를 가져오고, 퀴즈는 마지막 섹션 페이지로 렌더).
- **콘텐츠 파이프라인(핵심)**: `content/`의 2계층 — ① 레거시 날것 원본 `content/*.jsx`(+1 html, `/_source` 검수 전용, 앱이 직접 import 안 함) ② 구조화 챕터 `content/chapters/{id}/`(규약 v3: `meta.ts`·`body.tsx` 셔임·`intro/outro.mdx`·`sections/NN.mdx`·`figs.tsx` 등). 앱이 보는 통로: `content/registry.ts`(**수동 등록** 목록, 배열 순서=학습 순서) → `lib/content.ts`(앱↔콘텐츠 **유일 통로**, schema 타입을 그대로 재노출·어댑터 없음). **마이그레이션 현황 세는 법**: 구조화 챕터 수 = `content/chapters/` 하위 디렉터리 수, 원본 수 = `content/*.jsx` 개수, 계획 총수 = `CURRICULUM.md` 챕터 수. 세어서 기록.
- **상태·진도**: `lib/progress.ts` — 단일 localStorage 키 기반, **로그인 없음**, 디바이스 로컬. SSG는 빈 진도로 렌더 후 `useEffect`로 채우는 hydration 처리. 파싱 실패는 삼켜 빈 진도로 degrade.
- **빌드·검증·하네스**: `scripts/`(`validate-content.mts`=tsc가 못 잡는 값 수준 계약 검사, `gen-source-routes.mjs`=/_source 라우트 코드생성, `import-drills.mts`, `git_guard.py`=PreToolUse 훅=gh 차단·파괴 명령 차단), `.claude/settings.json` 훅 등록, CI.
- **기여 규칙**: `CLAUDE.md`의 브랜치 전략·이슈 단일진실·에픽 큐·`/land` 착지, `.claude/skills/`.

### 2. 산출물 — `docs/ARCHITECTURE.md` (신규 생성; 이후 재실행 시 갱신)
아래 구조로 쓴다(이해 흐름 순서 — 문서 상태 → 큰 그림 → 세부 → 기여). 각 절은 짧고 스캔 가능하게, 필요한 곳에 mermaid.

0. **문서 메타** — 최종 반영 날짜 + 점검한 커밋 SHA(`git rev-parse --short HEAD`로 세션이 기록). "살아있는 문서 — 구조가 바뀌면 이 프롬프트를 재실행해 갱신"이라는 한 줄. 재확인 기준점이 없으면 문서가 조용히 낡는다.
1. **한눈에** — 첫 2~3문장은 **평이한 말로**: 무엇인지·누구를 위한지("한국어, AWS DVA-C02 시험 대비 Next.js 정적 학습 사이트"). 이어서 핵심 기술 결정 3~5줄. 공개 독자가 여기만 읽어도 감이 오게.
2. **빠른 시작** — 실제 실행 명령으로: `npm install` → `npm run dev`(Next dev, 포트 3000; `predev`가 /_source 라우트 코드생성을 자동 선행하니 수동 단계 없음) → 브라우저에서 열기. 패키지 매니저는 **npm 고정**(`package-lock.json` 커밋, yarn/pnpm 금지). **선행 조건 = Node 버전**: 리포가 `engines`/`.nvmrc`로 못 박아두지 않았다(온보딩 갭 — 문서에 그 사실을 밝혀라); Next 16 + React 19 기준 Node 20.9+ 필요(권장 22 LTS 이상, CI는 24 사용). 추측하지 말고 이 근거대로 명시.
3. **큰 그림** — 스택(Next.js·React·MDX·TypeScript)과 **왜 SSG인지**(`output: "export"`=서버 런타임 없음), 배포 파이프라인. + 시스템 지도 mermaid.
4. **디렉터리 지도** — 최상위 폴더가 각각 뭘 담는지 표 또는 주석 트리(`app/`·`content/`·`lib/`·`scripts/`·`docs/`·`.claude/`). "이거 고치려면 어디 보나"에 답하도록.
5. **콘텐츠 파이프라인** — 2계층·규약 v3·`registry`→`lib/content` 통로·마이그레이션 현황(§1의 세는 법으로 얻은 수치). 이 프로젝트의 심장. + 파이프라인 mermaid.
6. **상태·진도** — 진도가 어떻게 저장/복원되나(localStorage 단일 키, 로그인 없음, 디바이스 로컬). **아직 안 하는 것을 사실로 기술**(계정·서버 저장 없음, 퀴즈 결과 미영속). 평가·부채 판정은 하지 마라 — 그건 `아키텍처점검.md` 몫.
7. **빌드·검증·하네스** — 스크립트 체인과 각 게이트가 뭘 막나(`validate-content`·`tsc`·`git_guard`·CI). CI는 develop만 트리거하고 빌드는 Vercel이 한다는 점 포함. + 게이트 mermaid.
8. **기여 흐름** — 브랜치 전략·이슈 단일진실·에픽 큐·`/land` 착지를 `CLAUDE.md`에서 **요약**(전문 복붙 아닌 요지 + 링크).
9. **용어·더 읽기** — 약어 사전(SSG·MDX·규약 v3·hydration·`/_source` 등) + `CLAUDE.md`·`CURRICULUM.md`·`APP_ARCHITECTURE_DRAFT.md`(제안)·자매 진단 프롬프트로의 링크.

#### 2-A. 다이어그램 (mermaid — `docs/`의 .md는 GitHub·Vercel 프리뷰가 그대로 렌더. 앱 MDX 파이프라인과 무관하니 콘텐츠 코드펜스 규정에 얽매이지 않음)
**실제 코드에서 확인한 것만 그린다 — 상상 금지.**
- **시스템 지도**(flowchart): 요청 → 라우트(`[id]` 목차 / `[id]/[sec]` 읽기) → `loadBody` 동적 import(섹션 렌더) → 콘텐츠 계약(schema/registry/lib) → 상태(localStorage). 서버 렌더 경계·`"use client"` 구분 표기.
- **콘텐츠 파이프라인**(flowchart): 레거시 원본 `content/*.jsx`(→ /_source 검수) 대 구조화 챕터 → `registry` 수동 등록 → `lib/content` → 렌더. 마이그레이션된 것/남은 것 색·주석 구분.
- **빌드·검증 게이트**(flowchart 또는 sequenceDiagram): `predev`·`prebuild`·`validate`·`gen-source-routes`·`git_guard`·CI가 각각 언제 뭘 하나(무엇을 막나).
- (선택) **디렉터리 지도**를 graph로.
- ⚠ **mermaid 문법 주의**: 노드 라벨에 `/` `.` `[]` `()` `{}` 가 들어가면 **반드시 큰따옴표로 감싼다** — 예: `N["app/chapters/[id]/[sec]"]`. 안 그러면 대괄호·중괄호를 문법으로 오인해 GitHub 렌더가 깨진다. 줄바꿈은 `<br>`. 커밋 전 각 코드블록을 눈으로 렌더 확인.

### 3. 톤·품질
- 리포 문서 스타일(간결·이유 명시)이되, 자매 진단문보다 **더 친절하게** — 처음 보는 사람이 독자다. 전제 지식 최소.
- 정확성 > 완성도. 확인 못 한 건 "확인 필요"로 표시하되 추측을 사실처럼 쓰지 마라. 특히 `APP_ARCHITECTURE_DRAFT.md`의 제안을 현행처럼 옮기지 마라(부록 A 함정).
- 분량은 스크롤 몇 번에 다 읽히게. 길면 절을 쪼개되 문서는 1개 유지.

### 4. 착지 (그리고 세션이 짧으면)
- 새 docs 파일도 하나의 작업 단위다 — `/write-issue`로 추적 이슈를 만들고(선택), 완료 후 `/land`로 착지(기본 PR, 본문 `closes #N`). **gh 차단 머신이면** 이슈는 GitHub 웹으로, 착지는 plain git으로(CLAUDE.md 프로세스 규칙).
- **최소 착지선(짧은 세션 대비)**: 1회차는 §2의 문서 메타·한눈에·빠른 시작·디렉터리 지도 + 시스템 지도·콘텐츠 파이프라인 2개 다이어그램까지를 착지 하한선으로 잡고, 나머지 절·다이어그램은 재실행에서 채운다. 살아있는 문서이므로 증분이 정상이다.

### 금지
- 문서 완료 전 앱·콘텐츠 코드 수정 금지.
- `content/` 수정 금지 — 문제가 보이면 고치지 말고 문서/이슈에 기록만.
- 진단문으로 변질 금지(점수·심각도 부채 목록은 자매 프롬프트 몫).
- `APP_ARCHITECTURE_DRAFT.md`·`docs/_frozen/`의 제안을 현행으로 옮기지 마라.
- 이 프롬프트/부록 A의 스냅샷을 실제 코드보다 우선하지 마라.

## 부록 A — 현행 핵심 사실 스냅샷 (2026-07-22 기준 · **반드시 코드로 재확인**)

아래는 세션을 빠르게 태우기 위한 검증된 출발점이다. 날짜가 지나면 낡을 수 있으니 §1에서 코드로 재확인하고, 어긋나면 실제를 따른다.

**스택·빌드·배포**
- Next.js 16 + React 19 + MDX(`@next/mdx`), TypeScript strict. `next.config.ts`에 `output: "export"` → 순수 SSG(서버 런타임 없음; 이걸 벗는 게 서버 기능의 유일 스위치).
- MDX는 `createMDX({})` **빈 설정** — remark/rehype 플러그인 금지(Next 16+Turbopack 불안정, #15). `mdx-components.tsx`가 마크다운 프리미티브를 콘텐츠 팔레트에 매핑.
- 스크립트: `predev`=gen-source-routes(선행), `dev`=next dev, `validate`=validate-content.mts, `prebuild`=validate + gen-source-routes --build, `build`=next build, `typecheck`=tsc --noEmit. `prebuild`에는 typecheck/validate:test **없음**.
- CI(`.github/workflows/ci.yml`)는 **develop만** 트리거(PR+push), `npm ci`·typecheck·validate·validate:test 실행, **빌드는 안 함**(Vercel 프리뷰가 담당). Node 24 고정.
- Vercel 설정은 대시보드(리포에 `vercel.json` 없음).

**라우팅·렌더링**
- `loadBody` = `ChapterEntry`의 프로퍼티(`content/registry.ts`), `() => import("./chapters/{id}/body")`. `app/chapters/[id]/[sec]/page.tsx`에서 호출, **섹션 단위**(0-based `section` prop) 렌더러를 가져온다(챕터 전체 아님).
- 퀴즈는 별도 라우트가 아니라 **마지막 섹션 페이지**(`n===total`일 때 `<ChapterQuiz>`가 `<Body>` 대신 렌더). `sectionCount()`가 퀴즈 위해 +1.
- 서버 컴포넌트: `layout.tsx`·`page.tsx`·`chapters/[id]/page.tsx`(목차)·`chapters/[id]/[sec]/page.tsx`(읽기). 클라이언트(`"use client"`): `home-progress`·`mark-read`·`section-concepts`·`chapter-quiz`·`section-toc`. (`progress-bar.tsx`는 지시어 없지만 import로 클라 번들에 포함.)
- 두 동적 라우트 모두 `generateStaticParams`+`dynamicParams=false`(output:export 제약).
- `/_source` = dev/프리뷰 전용 원본 검수 도구. 레거시 원본을 **문자열로 읽어 브라우저 Babel로 변환**(import·번들 안 함). `app/%5Fsource/`는 gen-source-routes 생성물+gitignore, 손대지 말 것.

**콘텐츠·계약·상태**
- `content/schema.ts` = 규약 v3(CONFIRMED), 타입·계약 단일 진실. `content/registry.ts` = **수동 등록**(손으로 쓴 import + `ChapterEntry[]`, 순서=학습 순서). `lib/content.ts` = **유일 통로**(schema 타입 그대로 재노출, 어댑터/평행 타입 없음). 헬퍼: `getAllChapters`·`getChapter`·`sectionCount`·`conceptsForSection`·`groupByPhase`·`globalQuestionKey`.
- 마이그레이션 = **4/24**: `content/chapters/`에 ch0-1·ch0-2·ch1-1·ch1-2(전부 registry 등록). `session`은 **ch0-1만** 보유. `CURRICULUM.md`는 24챕터 계획.
- 레거시 = `content/*.jsx` 27개(+`aws-dva-stage0.html` 1개). 앱이 import 안 함(/_source만 접근). 서비스 중복 원본 다수(iam 2개, lambda 2개 등) → 원본 27개가 챕터와 1:1 아님. `content/dva-chapter-template.jsx`는 스캐폴드.
- `lib/progress.ts` = 단일 키 `"aws-reps.read.v1"`, 모델 `Record<string, number[]>`(읽은 섹션 번호, 1-based, 퀴즈 페이지 포함). 로그인 없음, 디바이스 로컬, 파싱 실패 시 빈 진도.
- `scripts/validate-content.mts` = 값 수준 계약(ID 전역 유일·섹션≥1·섹션번호 유일·prereq 실재·선택지≥2·정답 범위·세션 규칙 등)을 prebuild·CI에서 강제.
- `scripts/git_guard.py`(PreToolUse 훅) = gh CLI 차단(홈 마커+padahkim 계정일 때만 허용)·파괴 명령 차단(rm -rf, force push, reset --hard 등).

**⚠ 제안 vs 현행 — `APP_ARCHITECTURE_DRAFT.md`의 함정(초안대로 쓰면 허구를 씀)**
- 초안의 `lib/contract/` 3파일 어댑터+평행 타입(AppChapterMeta 등) → **미구현**. 현행은 `lib/content.ts` 단일 파사드.
