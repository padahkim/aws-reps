> **저장 위치**: `docs/prompts/규약사전분석_스프린트.md`
> **목적**: 축1 완료를 기다리지 않고, 규약 v1의 **평가-독립적 결정 포인트**를 선행 분석하고 규약 v0를 실제 콘텐츠에 스트레스 테스트한다. 산출물은 ③규약제안 세션과 ④인간 결정의 입력이 된다.
> **실행**: 프로젝트 루트, 새 세션. 사고 깊이를 높여라(`/effort high`, 핵심 분석 구간에서 ultrathink). 플랜 모드 불필요 — 시간이 자산이므로 바로 작업한다.
> **전제**: reports/axis2/에 리포트가 일부라도 존재해야 한다(스트레스 테스트 표본용).

## 프롬프트 본문 (아래부터 복사)

너는 **규약 사전분석가**다. 가용 시간은 약 50분으로 제한된다. 임무는 아래 우선순위 순서대로이며, **각 산출물 섹션은 완성되는 즉시 파일에 저장하고 커밋하라 — 마지막에 몰아서 저장하는 것을 금지한다.** 중간에 세션이 끊겨도 커밋된 만큼이 자산으로 남아야 한다.

### 0. 준비 (5분 이내)
- 정독: `docs/CURRICULUM.md` §1(하이브리드·Next.js 확정)·§3(규약 v0)·§4(앱 요구사항), `BOARD.md`. RUBRIC은 §8의 L 항목 이름만 참조하면 된다(전문 정독 불필요 — 시간 절약)
- BOARD 단계 2 표에 자기 행을 추가하라: `| 2-0a | 규약 사전분석 스프린트 | 사전분석 세션 | 진행 | docs/CONTRACT_PREWORK.md | 평가-독립 결정 포인트 선행 |` — 그리고 세션 로그에 한 줄 append. 다른 행 수정 금지

### 1. 최우선 (~25분) — 규약 v0 스트레스 테스트

`reports/axis2/`에 리포트가 **이미 존재하는** 콘텐츠 중, 형식 태그가 서로 다른 파일 2~3개를 골라라(형식 태그가 아직 없으면 육안으로 형식이 달라 보이는 것). 각 파일에 대해 규약 v0로의 변환을 **문서 안에서 시뮬레이션**하라 — 실제 코드 파일 생성이나 /content 수정은 금지, 변환 스케치는 CONTRACT_PREWORK.md 안에만 쓴다:

- 이 파일의 어떤 정보가 `meta`에 담기지 않는가 (필드 부족)
- 이 파일의 문항 중 `quiz` 구조(scenario/choices[4]/answer/explanation)에 안 맞는 유형이 있는가 (예: 드래그 정렬, 빈칸, 선택지 3개)
- 본문에서 분리하기 곤란한 인터랙션·상태가 있는가 ("use client" 경계와 얽히는 것)
- 이 파일 하나의 표준화 실작업량 추정 (몇 분짜리 작업인가, 기계적인가 판단이 필요한가)

산출: `docs/CONTRACT_PREWORK.md` **§1 스트레스 테스트 결과** — 파일별 발견 사항 + "v0가 놓치고 있는 것" 종합 목록. **완성 즉시 저장·커밋.**

### 2. 차순위 (~15분) — 평가-독립 기술 결정 포인트 심층 분석

다음 결정 포인트들을 Next.js App Router 관점에서 깊게 분석하라. 각 포인트마다 선택지, 기술적 트레이드오프(번들 크기·SSG/CSR 경계·빌드 포함 방식·유지보수), 그리고 너의 권고와 근거:

1. `"use client"` 선언 위치 — 각 챕터 모듈 상단 vs 로더 래퍼 한 곳 (서버 컴포넌트 이점을 포기하는 범위 포함)
2. 메타 export 명명 — `meta` vs `chapterMeta` (Next 예약 `metadata`와의 혼동 비용)
3. 챕터 동적 로딩 전략 — `next/dynamic` + 정적 import map vs 기타 (`/content`가 `app/` 라우트 밖에 있을 때 빌드에 포함되는 방식, 챕터 수 증가 시 확장성)
4. `quiz` 필드 설계 — `scope` 어휘, 문항 id 규칙(챕터 접두 등), `concept` 태그 의무 여부 (스트레스 테스트 §1에서 발견한 비정형 문항 유형의 수용 방안 포함)
5. 본문 내 문항 배치 API — `<Quiz ids={[...]} />` 형태의 인터페이스 초안

**단, 표현 형식의 우열(형식 낙점)은 절대 건드리지 마라 — 그것은 축1 점수라는 평가 증거의 몫이다.** 산출: CONTRACT_PREWORK.md **§2 기술 결정 포인트 분석**. 완성 즉시 저장·커밋.

### 3. 시간이 남으면 — 규약 변경에 강건한 앱 스켈레톤

`docs/APP_ARCHITECTURE_DRAFT.md`: 규약 의존 지점을 **어댑터 한 겹으로 격리**하는 Next.js 구조 초안 — 디렉터리 트리, 라우팅(`app/chapters/[id]`), 진도 저장 설계(localStorage 키 구조), 공용 `<Quiz>`의 대략적 props 경계. 목적: 규약 v1이 확정되면 어댑터 부분만 채우면 되도록. 코드 구현은 금지, 설계 문서만.

### 4. 종료 절차 (시간 잔량 2~3분이 되면 무조건)
작업을 멈추고: 최종 커밋 → BOARD 2-0a 행을 `정지-승인대기`로, 승인 대기함에 "CONTRACT_PREWORK 검토" 등록 → 세션 로그에 "어디까지 완료, 무엇이 미완"을 한 줄로 남기고 종료하라.

### 금지 사항
- 규약 확정 어조 금지 — 전부 제안형. 확정은 인간이 ④에서 한다
- /content·RUBRIC·CURRICULUM·PLAYBOOK 수정 금지, 코드 파일 생성 금지
- 평가 리포트의 판정 재해석 금지, 형식 우열 판정 금지
- 임무 1을 건너뛰고 2·3으로 가는 것 금지 — 실물 콘텐츠와의 충돌 발견이 이 스프린트의 최고 가치다
