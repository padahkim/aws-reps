## 프롬프트 본문 (아래부터 복사)

너는 이 세션에서 **앱 트랙 담당**이다. 이 프로젝트는 AWS DVA-C02 학습 웹앱이고, 콘텐츠 쪽 작업(평가·규약 확정·표준화)은 완료되었다. 네 임무는 ① 기존 앱 코드를 진단해 리팩터링/재작성을 권고하고 ② 승인 후 **Next.js(App Router)+TypeScript 셸**을 마일스톤 단위로 구축하는 것이다.

### 1. 기준 정독
`docs/CURRICULUM.md`(특히 §1 하이브리드 아키텍처, §3 **확정된 규약 v1**, §4 앱 요구사항, §6 작업 규칙), `PLAYBOOK.md` §3·§4, `BOARD.md`를 정독하라. 콘텐츠 품질이 궁금하면 `reports/`를 참조하되 — **콘텐츠를 재진단하지 마라. 콘텐츠 평가·표준화는 완료된 사안이다. 네 진단 범위는 앱 코드만이다.**

### 2. 워커 리추얼 (BOARD)
BOARD의 네 임무 행(4-1, 4-3)을 확인하고, 정지 지점·마일스톤마다 자기 행 갱신 + 세션 로그 append. 다른 행 수정 금지.

### 3. 1차 임무 — 앱 코드 진단 (읽기 전용, 수정 절대 금지)
1. **현황 파악**: /content와 docs를 제외한 앱 코드의 파일 트리, 스택·의존성, 빌드·실행 여부. 깨져 있으면 원인만 파악
2. **스택 확인**: 기존 코드가 Next.js가 아니라면(예: Vite CRA 등) **마이그레이션 비용을 리팩터링 vs 재작성 판단에 반드시 포함**하라
3. **갭 분석 — "규약 기반 셸" 관점**: 목표 앱은 본문 렌더러가 아니라 **규약 export만 소비하는 셸**이다 — ① 챕터 로더(`app/chapters/[id]` + 동적 import) ② `meta` 수집 네비게이션+진도 ③ 공용 `<Quiz>`+오답 노트. 기존 코드에서 이 3요소 관점으로 살릴 것과 없는 것을 가려라
4. **진단 리포트**: 살릴 자산 / 버릴 것과 이유 / **권고: A) 기존 리팩터링 vs B) Next.js 새 스캐폴드 + 자산 이식** — 각 안의 예상 마일스톤 수와 근거, 네 추천
5. 여기서 정지. BOARD 승인 대기함에 올리고 내 결정을 기다려라

### 4. 2차 임무 — 실행 (내가 A/B를 승인한 후에만)
- **A 리팩터링**: 마일스톤 계획 수립. 규약 기반 로더 도입을 최우선 마일스톤으로
- **B 재작성**: Next.js 스캐폴드 계획 + 살릴 자산 이식 계획. 기존 코드는 삭제하지 말고 `legacy` 브랜치(또는 폴더)로 보존
- 어느 쪽이든 마일스톤 순서: 스캐폴딩+규약 로더 → meta 네비+진도 → 공용 `<Quiz>`+오답 노트 → 표준화된 /content 실데이터 검증. 마일스톤마다 실행 가능한 상태로 커밋
- 완료 시 프로젝트 루트에 `CLAUDE.md` 생성, 다음 규칙 명시: ① 콘텐츠 평가·검증 기준은 docs/RUBRIC.md ② 신규 콘텐츠는 규약 v1 준수 + 신규 모드 파이프라인 통과 후에만 /content 진입 ③ 상태 갱신은 BOARD.md ④ 마일스톤 단위 커밋

### 5. 금지 사항
- `/content` 수정 금지 — 앱은 챕터 모듈을 **로드만** 한다. 콘텐츠에 문제가 보이면 수정하지 말고 보고하라
- RUBRIC·CURRICULUM·PLAYBOOK 수정 금지
- 진단 승인 전 어떤 코드도 수정 금지
- 규약 v1과 다른 데이터 모델을 임의 도입 금지 — 변경이 필요하면 제안하고 승인받아라
