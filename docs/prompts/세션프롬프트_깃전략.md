## 프롬프트 본문 (아래부터 복사)

너는 이 세션에서 **Git 운용 전략 설계자**다. 1인 프로젝트에 맞는 최소한의, 그러나 일관된 브랜치·PR·워크트리 규칙을 설계해 `docs/GIT_STRATEGY.md` 한 페이지로 만든다. 규칙이 많을수록 안 지켜진다 — **한 페이지를 넘기면 실패**로 간주하라.

### 0. 정독과 제약 파악
- `docs/RUBRIC.md` §6(워크트리 병렬 규칙 — eval/axis1·axis2 브랜치, 쓰기 경계, 커밋 동기화), `PLAYBOOK.md` §1(운영 루프)·§4(단계 지도), `BOARD.md`
- `git branch -a`로 현존 브랜치 인벤토리 (main, eval/*, 워크트리 자동 생성 브랜치 등)
- **새 전략은 기존 규칙과 모순되면 안 된다**: eval/axis* 네이밍은 이미 문서에 박혀 있으므로 전략이 이를 수용하거나, 변경 제안 시 영향 범위(RUBRIC §6, 세션 프롬프트들)를 명시하라

### 1. 설계할 내용 (docs/GIT_STRATEGY.md 의 구성)

**① 브랜치 모델**: 1인 프로젝트 기준으로 GitHub Flow 계열(main + 단명 작업 브랜치)을 기본으로 하되, 이 프로젝트 특성(문서 중심 파이프라인 + 앱 트랙)에 맞게 조정하라.

**② 브랜치 네이밍 규칙**: `카테고리/설명` 형식으로 확정하라. 카테고리는 이 프로젝트의 실제 작업 종류에서 도출: 예) `eval/*`(평가 — 기존 axis1·axis2 수용), `content/*`(콘텐츠 표준화·생성), `app/*` 또는 `feat/*`(앱 기능), `fix/*`, `docs/*`, `sprint/*`(단발 분석). 설명부는 kebab-case. 정규식 한 줄로 표현 가능해야 한다(검증 스크립트용).

**③ PR 기준 (솔로 현실형, 계층화)**:
- main 직커밋 허용: 문서(docs/, BOARD, PLAYBOOK), 평가 리포트(reports/)
- PR 필수: 앱 코드 — 단위는 PLAYBOOK의 마일스톤. PR 셀프 체크리스트(빌드 통과, BOARD 갱신 포함, 규약 준수 등) 5개 이내로
- 머지 방식(squash vs merge commit)과 브랜치 삭제 규칙

**④ 워크트리 규칙**: 워크트리 디렉터리 위치·명명, "워크트리 1개 = 동시 세션 1개" 원칙, 작업 완료 후 정리 절차. Claude Code가 자동 생성하는 워크트리 브랜치의 처리 방침(허용 프리픽스로 수용할지, 완료 시 정리 규칙)

**⑤ 커밋 메시지 규칙**: Conventional Commits 최소형(`type: 요약`) — 기존 커밋 이력과 급격히 어긋나지 않는 선에서

### 2. 시행 장치 (설계 + 초안 작성, 설치는 인간 승인 후)

1. **`scripts/check-branch-name.sh`**: 현재 브랜치명이 ②의 정규식에 맞는지 검사하는 스크립트 + git pre-push 훅으로 거는 설치 방법 주석. 누가(UI든 세션이든 사람이든) 브랜치를 만들었든 푸시 시점에 걸리는 최종 방어선이다
2. **Claude Code WorktreeCreate 훅 초안**: 워크트리 생성 로직을 대체해 네이밍 규칙을 적용하는 훅 설정(JSON) 초안 — 설치 파일 경로와 방법을 명시하되 **직접 설치하지 마라**, 초안과 설치 절차만 GIT_STRATEGY.md 부록에
3. **CLAUDE.md 추가 문구 초안**: "브랜치·워크트리 생성 시 docs/GIT_STRATEGY.md의 네이밍을 따른다. 위반 이름 발견 시 `git branch -m`으로 정정한다" — 단계 4에서 CLAUDE.md가 생성될 때 넣을 문구로 GIT_STRATEGY.md 부록에
4. **PLAYBOOK 반영 제안**: PLAYBOOK §2 문서 표에 GIT_STRATEGY.md 한 줄을 추가하는 제안 텍스트 — **PLAYBOOK을 직접 수정하지 마라**, 제안만

### 3. 완료 절차
`docs/GIT_STRATEGY.md`와 `scripts/check-branch-name.sh`를 커밋하고, 다음을 보고하라: 기존 브랜치 중 규칙 위반 목록과 정리안(rename/삭제 — 실행은 인간 승인 후), PLAYBOOK 추가 제안 문구, 설치가 필요한 항목 체크리스트. 그리고 종료하라.

### 금지 사항 (병렬 충돌 회피 포함)
- **BOARD.md 수정 금지** — 병렬로 도는 스프린트 세션과의 충돌 방지. 완료 보고만 하면 인간이 로그에 기록한다
- RUBRIC·CURRICULUM·PLAYBOOK 수정 금지 (제안만)
- 쓰기 허용 범위: `docs/GIT_STRATEGY.md`, `scripts/` 두 곳뿐
- 기존 브랜치의 rename·삭제 실행 금지 (목록화와 제안만 — 실행은 인간)
- 훅·설정 파일의 실제 설치 금지 (초안과 절차만)
- 규칙 과잉 금지: 본문 한 페이지 초과, 체크리스트 5개 초과, 카테고리 7개 초과면 스스로 줄여라
