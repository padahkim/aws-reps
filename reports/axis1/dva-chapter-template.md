## 수정 지시

축1 판정 통과 — 축1 관점 필수 수정 없음. (종합 판정은 축2의 커버리지 보강 완료에 게이트됨.)

1. **L3 상향(선택, 1→2)**: 개념 카드 `a`/`why` 안에 개념 직후 구체 예시를 결합. 예 — c2(DynamoDB 일관성)에 `GetItem --consistent-read` CLI 한 줄, c3(프록시 통합)에 프록시 이벤트 JSON 골격 1개. 현재 예시가 퀴즈로만 분리돼 개념-예시 인접성이 끊김.
2. **L6 상향(선택, 1→2)**: 각 개념 카드에 선행 챕터 1개 명시 지목(예: c1 콜드스타트 → "1-2 Lambda 실행 환경 수명주기", c4 동시성 → "다운스트림 RDS 커넥션 = 5-4 RDS").

## 보충 생성 목록 (결손 성분)

- **[예시 결손, L3]** 개념 카드 4종에 개념-직후 결합 예시(CLI/JSON/코드 골격) 생성.
- (축2 위임) 커버리지 보강(Lambda 오류처리·버전별칭 / DDB 키설계·GSI vs LSI·Query vs Scan / API GW 인증 4종·스테이지)은 축2 수정 지시 소관 — 축1은 해당 신규 블록 생성 시 위 L1·L2·L7·L8 모범 패턴을 동일 적용할 것을 권고.

## 반복 약점 메모

- **L3 개념-예시 분리**: 설계가 아무리 우수해도 구체 예시(CLI/JSON)를 개념 블록 밖(퀴즈)으로 몰면 L3이 1에 묶임. 생성 프롬프트에 "개념 카드 본문 내 실전형 예시 1개 인라인 결합" 규칙 추가 권장.
- **L6 선행 브리지 부재**: 여러 파일에서 반복될 조짐(messaging에서도 동일). 생성 프롬프트 공통 체크리스트로 격상 필요.
