## 수정 지시
1. **L6 위반(코퍼스 공통) — 명시적 선행 챕터 역참조 부재.** 현재 도커·서버리스는 "선수 개념/복습" 배지로 파일 내부에 삽입돼 있으나 "어느 장에서 배운" 지목이 없다. 구체 삽입점:
   - **정책 템플릿 섹션 도입부(L2214-2221, "Lambda가 다른 서비스에 접근하려면 IAM 권한이 필요합니다")** 뒤에 명시 지목 추가 — 예: "(0-x장 IAM 역할·신뢰 정책에서 배운 실행 역할이 여기 함수 `Policies`로 최소권한 부여된다)". *(정확한 장 번호는 콘텐츠 저자가 커리큘럼 대조 후 확정 — 축1은 사실 재검증 소관 아님, 번호 자리표시 유지)*
   - **CodeDeploy 섹션의 `AutoPublishAlias` 설명(L2327 / 콜아웃 L2451)** 뒤에 "2-x장 Lambda **버전·별칭(alias)** 개념이 여기 `AutoPublishAlias`의 전제" 식 선행 챕터 지목 추가 — 트래픽 전환의 전제를 앞 챕터에 명시적으로 걸면 L6=2 달성.
   - 주의: "387번/다음 섹션/도커 섹션과 연결" 류는 동일 챕터 내부 링크라 L6 상승에 무효. 반드시 **다른(선행) 챕터** 지목이어야 함.
2. (설계 유지 권고) `SamTransform`(L454-615)·`TrafficShift`(L620-929) 두 시뮬레이터는 L3 강점의 핵심이므로 유지. 단 축2 수정지시대로 `SamTransform`의 `resources` 배열(L464 `Logs::LogGroup`)은 제거/각주 처리 필요(사실 오류 — 축2 소관, 설계 점수 무관).

## 보충 생성 목록 (결손 성분)
퀴즈·해설 전면 결손이 이 파일 최대 산출물. 파일에 이미 **문항 소재가 풍부**(시험 포인트 콜아웃·치트시트 빈출 열·"함정 체크" 목록)하므로 이를 문항으로 승격:
1. **SAM 정체성/Transform** — "필수 암기 3가지" 콜아웃(L1773-1785) 소재. 4지선다: "SAM 템플릿으로 인식시키는 헤더는?"(정답 `Transform: AWS::Serverless-2016-10-31`), 오답에 `AWSTemplateFormatVersion`만 있는 버전 배치 → 해설로 "확장/상위집합" 개념 조건화.
2. **Canary vs Linear (최상위 빈출 ◆◆◆)** — warn 콜아웃(L2439-2449) 소재. 시나리오형: `Canary10Percent5Minutes`와 `Linear10PercentEvery1Minute`의 동작을 바꿔 제시하고 고르게 하는 함정형(축2가 "정의를 바꿔서 출제" 명시). 오답별 해설로 "2단계 vs 균등 증분" 구분.
3. **capabilities** — 콜아웃(L1985-1991) 소재. "이름 지정 IAM 리소스 생성 시 필요한 플래그?"(정답 `CAPABILITY_NAMED_IAM`), `CAPABILITY_AUTO_EXPAND`는 Transform/매크로용이라는 오답 조건화.
4. **정책 템플릿** — 콜아웃(L2299-2303) 소재. "이름+대상 리소스만 지정하면 최소권한 IAM 자동 생성" 진위/매칭 문항.
5. **sam local / start-api** — 콜아웃(L2529-2535) 소재. "API Gateway를 로컬 시뮬레이션하는 명령?"(정답 `sam local start-api`)+도커 필요 여부.
6. **Api 이벤트 자동 생성** — 콜아웃(L2112-2117) 소재. "함수 `Events`에 `Type: Api`만 달면 함께 자동 생성되는 것?"(API Gateway + **Lambda 호출 권한**).
7. **치트시트 표(L2645-2707)·함정 체크(L2741-2747)** 는 14행·6항이 그대로 문항 스템. 빈출 3(◆◆◆) 행 우선 문항화, 각 행 "한 줄 정리"를 정답지문·왜곡변형을 오답지문으로.

**축2 소관 커버리지 갭(위임 표기)**: `sam deploy --guided`·`samconfig.toml` 자동 생성 흐름 완전 누락(축2 수정지시 #2), "SAM Accelerate" 기능명 미표기(축2 누락 #2). 문항화 전 콘텐츠 보강이 선행돼야 하며 이는 축2/저자 소관.

## 반복 약점 메모
- **L6 명시 지목 부재 = 코퍼스 최다 반복 감점(9/9 파일째 L6=1).** 이 파일은 오히려 선수 개념을 **파일 내부에 통째로 삽입**(도커·서버리스 복습 섹션)해 선(先)지식 관리를 잘하는 편이나, 그럼에도 "N-N장" 형식의 **선행 챕터 역참조**는 없다 → 앵커상 여전히 1. 생성 프롬프트에 "능동적으로 앞 챕터 번호를 지목해 개념을 재소환하라(inline 복습 삽입만으로는 부족)"를 명시 강화 권고.
- 신규 임포트 파일 특성상 내부 계층 scaffold(학습 지도)는 우수 — 이 강점은 유지하되 외부(선행 챕터) 연결만 추가하면 L6=2 즉시 달성 가능한 구조.

## 스키마 피드백 요약
- **"함정 체크" 목록(L2739-2773) + 치트시트 "빈출" 열(L2626)** 은 v0 스키마가 별도 태깅하지 않는 구조지만, **퀴즈 생성 시 오답 유도·난이도 배분 소재로 직결**된다(함정 체크 6항 = 그대로 오답지문 풀). "코드+해설" 쌍은 부재(해설 성분 없음). 축1 관점 신규 제안: 성분 스키마에 `trap_list`(오답 소재)·`freq_tag`(빈출 등급) 필드를 추가하면 생성 파이프라인이 문항·오답을 자동 도출 가능.
- 인터랙티브 시뮬레이터 2종(상태기계형 `TrafficShift`·익스팬더형 `SamTransform`)은 축2가 이미 `SCHEMA_FEEDBACK_AXIS2.md`에 등재. 축1 관점에선 이들이 **L1(채점형 인출)이 아니라 L3(능동 예시)에만 기여**한다는 경계를 스키마에 명시할 것(시뮬레이터≠퀴즈).
