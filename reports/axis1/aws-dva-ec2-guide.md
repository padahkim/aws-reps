# 축1 리포트: aws-dva-ec2-guide

**모드**: 레거시 / **평가 범위**: 부분 평가 (N/A: L1·L2·L7·L8 — 퀴즈 성분 없음) / **판정: 수정** (유효 총점 6/8 = 75%)

> 축2 판정: 수정(gp3 최대 IOPS·EFS Elastic 처리량이 구식 수치 2건 — 설계가 아닌 사실 오류). **두 축 종합 = 수정**.
> 성분 태그(축2): 설명 O · 예시 O(다이어그램·표·시험포인트) · 퀴즈 X · 해설 X / 매핑: 4-0 컴퓨팅 기초(EC2 부분).

## 채점표
| 항목 | 점수 | 근거(구체 위치 인용) |
|---|:--:|---|
| L1 인출 밀도 | N/A | 채점형 퀴즈 없음. `ExamTip`(시험 포인트) 콜아웃은 "시나리오→정답" 서술이라 학습자 응답을 요구하지 않음 → 문항 아님(N/A 규칙). 시뮬레이터/슬라이더 없음(IntersectionObserver는 내비 하이라이트 전용, 라인 1285~1296). |
| L2 해설 완전성 | N/A | 해설 없음(문항 부재) |
| L3 구체 예시 결합 | **2** | 각 개념 섹션이 **SVG 다이어그램을 섹션 최상단에 즉시 배치**(예: `DiagramSG` 라인 1611, `DiagramEBS` 1905) + 개념 직후 `ExamTip`이 **실전 지문형 시나리오→정답**("인스턴스 시작 시 자동 웹 서버 설치 → User Data" 1550~1554; "Timeout=보안그룹, Refused=애플리케이션" 1680~1683; "볼륨 다른 AZ로 → 스냅샷 생성 후 복원" 1978~1982). CLI가 개념에 인접 인라인(`ssh -i mykey.pem ec2-user@퍼블릭IP` 1707, `chmod 400 mykey.pem` 1723~1724, `aws configure`/`aws iam list-users` 1761·1770). 예시가 개념과 인접·실전형 → 앵커 2(코퍼스 messaging·security-1 선례와 동형). |
| L4 인지부하 | **2** | 섹션이 개념 단위로 원자화(EC2 기초/유형/SG/SSH/역할/구매/EBS/스냅샷/AMI/스토어/볼륨유형/Multi-Attach/EFS/비교). 약어 첫 등장 시 정의: EC2=Elastic Compute Cloud·IaaS(1493), ELB·ASG 풀네임(1504~1507), 볼륨 유형 6종은 표로 일괄 정의(2061~2120), EFS 모드 다수 용어를 표로 관리(2194~2240). 구매 옵션 8종·EFS 모드 다수도 표 셀에 각각 정의돼 있어 "8개↑ 미정의" 조건 미해당 + 호텔 비유(1853~1859)·빈출 게이지로 부하 완화 → 앵커 2. |
| L5 시험무관 분량 | **1** | 축2 범위이탈: **"AWS Budgets 섹션(LECTURE 31)…freq=1로 자체 저비중 표기됨. 전체 16개 섹션 중 1개, 분량도 짧아 '경미' 수준(10% 미만)"** 인용. 축2가 "없음"이 아니라 경미 이탈을 기술 → 앵커 1(해당 섹션은 라인 1452~1482). 퍼블릭 IPv4 요금(45)은 축2가 "이탈로 보지 않음"으로 제외. |
| L6 선행 지식 연결 | **1** | 명시적 "N-N장/특정 선행 개념" 역참조 부재. IAM 역할 원칙(1780~1788)은 "EC2/Lambda/ECS에서 자격 증명 필요 시 IAM Role"이라는 **서비스 일반 원칙**이지 선행 IAM 장(신뢰 정책·AssumeRole) 명시 지목 아님. "거부가 필요하면 NACL"(1620), "DVA는 SAA와 달리"(1427~1431)도 배경/시험 비교 언급 수준. EBS·ELB·ASG 참조는 동일 챕터(4-0) 내부라 L6 대상 아님 → 앵커 1(코퍼스 8개 전부와 동일). |
| L7 난이도 분포 | N/A | 퀴즈 없음 |
| L8 누적 복습 | N/A | 퀴즈 없음 (단일 챕터 4-0 담당 — A3 적용) |
| **유효 총점** | **6/8** | **75% → 수정** (60~85% 구간). 두 축 종합도 수정. |

## 수정 지시

1. **L6 위반(핵심 감점) — IAM 역할 섹션(라인 1780~1788 `ExamTip`)에 선행 장 명시 지목 추가.** 현재 "자격 증명 필요 시 IAM Role"은 서비스 일반 원칙. → "IAM 챕터에서 배운 **신뢰 정책(Trust Policy)의 AssumeRole**이 여기 EC2 인스턴스 프로파일에 그대로 적용된다"처럼 **선행 IAM 개념을 명시 역참조**로 승격. (2점 조건 = 챕터·개념 명시 지목.)
2. **L6 보강 — 보안 그룹 섹션(라인 1620, "거부가 필요하면 NACL")** 을 "VPC 챕터의 NACL(스테이트리스·거부 규칙)과 대비"로 **선행/연계 챕터를 명시**해 배경 언급을 지목형으로 전환.
3. **L5 개선 — Budgets 섹션(라인 1452~1482)** 은 축2가 경미 이탈로 기술한 유일 항목. 삭제까지는 불필요하나, 섹션 헤더에 "시험 저비중·실무 보조"를 명기하거나 접이식(collapsible)로 강등해 **시험 관련 분량과 시각적으로 분리**하면 L5 상향 여지.
4. (축2 소관 위임) voltype 표 gp3 행(라인 2067~2069)·efs Elastic 행(라인 2219~2221) 수치 갱신은 **사실 오류로 축2 수정 지시 소관** — 축1은 재검증 안 함, 설계상 위치는 적절하므로 값만 교체 권고.

## 보충 생성 목록 (결손 성분)

퀴즈·해설 전면 결손이 핵심 갭. 본 파일은 `ExamTip`·`Card tone="warn"`·비교표가 **문항 시드로 이미 완성돼 있어** 그대로 채점형으로 승격 가능:

- **보안 그룹 접속 오류**(라인 1647~1658·1680~1683): "SSH Timeout이 발생한다. 가장 가능성 높은 원인은?" 4지선다(정답: 보안그룹 인바운드 미허용) + 해설(Refused와 대비).
- **볼륨 유형 부팅 가능성**(라인 2121~2124): "부팅 볼륨으로 쓸 수 없는 것은?" (정답: st1/sc1) + 해설.
- **gp2 vs gp3**(라인 2125~2129): "IOPS를 크기와 독립적으로 올려 비용을 최적화하려면?" (정답: gp3) + 해설.
- **EFS vs EBS vs 인스턴스 스토어**(라인 2323~2328 즉답 공식): 시나리오 3종("다중 AZ 공유"/"단일 고성능 영구"/"최고 I/O 임시 OK") 매칭 문항 + 해설.
- **구매 옵션 매칭**(라인 1860~1864): 시나리오→옵션(Spot/Reserved/Dedicated Host) 매칭 + 해설.
- **User Data**(라인 1550~1554): "매 부팅 실행?"(정답: 최초 1회·root) 함정형 + 해설.
- **인스턴스 스토어 임시성**(라인 2046~2050): "데이터 유지 조건이 붙으면?" (정답: io2 EBS) + 해설.
- **Delete on Termination**(라인 1930~1942)·**Multi-Attach io1/io2·같은 AZ·16개**(라인 2141~2160)·**스냅샷 AZ/리전 이동**(라인 1978~1982)도 각 1문항 소재.
- 커버리지 갭: 축2가 "누락 없음(최소한 규정 대비 상세)"으로 판정 — 신규 커버 문항 위임 불필요.

## 반복 약점 메모

- **L6 명시 지목 부재 = 코퍼스 공통 패턴(8개 파일 전부 L6=1).** 본 파일도 IAM Role·NACL·SAA 비교를 서비스 일반/배경 언급 수준에서만 처리. 생성 프롬프트에 "각 개념마다 선행 챕터의 특정 개념을 'N-N장의 X가 여기 Y로 적용' 형식으로 최소 1회 명시 역참조" 규칙을 추가하면 코퍼스 전역 L6=2 상향 기대.

## 스키마 피드백 요약

- **`ExamTip`(시나리오→정답) 콜아웃과 `Card tone="warn"` 함정 포인트, 비교표 즉답 공식이 사실상 "문항 시드"** 로 이미 존재. v0 스키마에 이를 채점형 퀴즈로 자동 승격하는 `quiz-seed`(문두=시나리오, 정답=콜아웃 결론, 오답=인접 오개념) 필드를 신설하면 결손 성분(퀴즈·해설)을 저비용으로 충당 가능 — 축1 관점의 신규 구조 제안. FreqGauge/즉답표 자체는 축2가 이미 SCHEMA_FEEDBACK에 기록해 중복 생략.
