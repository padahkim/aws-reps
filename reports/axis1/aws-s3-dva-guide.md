## 수정 지시

축1 판정 통과 — 축1 필수 수정 없음. 종합 판정 게이트는 **축2 수치 오류(5TB→50TB 3곳)** 이며 이는 축2 소관.

1. **[L6 상향, 1→2 (선택·설계 개선)]** 선행 챕터 명시 지목 추가로만 2 획득 가능. 구체 지점:
   - S3-04 버킷 정책 설명(라인 2046~2051 "Principal 필드가 IAM 정책과의 큰 차이") → "0-2장 IAM 리소스 기반 정책과 동형 구조이며 Deny 우선 평가 로직이 동일하게 적용" 식 챕터 지목 문장 추가.
   - S3-05 SSE-KMS Fact(라인 2127~2129 "AWS KMS로 키 관리") → "3-2 KMS 챕터의 봉투 암호화(GenerateDataKey)가 여기 객체 암호화에 그대로 쓰인다" 브리지 추가.
   - S3-14 이벤트 대상 권한(라인 2552~2555) → "메시징 챕터의 SNS/SQS 리소스 정책 개념이 여기 S3 이벤트 권한 부여에 적용" 지목.

## 보충 생성 목록 (결손 성분)

- **[퀴즈·해설 전면 결손]** L1·L2·L7·L8 N/A의 원인. 최빈출 모듈(freq 5: S3-04 보안·버킷정책 / S3-05 암호화 / S3-11 스토리지 클래스)에 **적용형 시나리오 문항 + 오답 조건화 해설** 신규 생성 필요. 전환 소재가 이미 파일 내 존재:
  - S3-11 Exam 콜아웃(라인 2419~2424)의 "시나리오→클래스" 매핑 3쌍 → 4지선다 문항으로 직접 전환(오답: 인접 클래스 최소기간·검색속도 혼동). 난이도 최저 전환.
  - S3-05 Exam(라인 2155~2160) "직접 관리+미저장→SSE-C / 감사 필요→SSE-KMS" → 조건 조작형 문항. 오답 해설: SSE-C의 HTTPS 필수·키 미저장 vs SSE-KMS CloudTrail 감사 대비.
  - S3-13 복제 3대 함정(라인 2511~2516) → "기존 객체 미복제→Batch / 체이닝 불가 / 버전ID 삭제 미복제" 각각 True/False 자가채점 문항.
  - S3-14(라인 2560~2565) "SQS 알림 실패 원인" → 트러블슈팅 단답 문항.
- **[커버리지 — 축2 소관]** 축2 "누락: 없음" 확인. 단 전송 중 암호화 강제(`aws:SecureTransport` Deny) 블록 보강 권장은 축2 위임 항목(Task 2.2 관점).

## 반복 약점 메모

- **퀴즈·해설 부재** → L1·L2·L7·L8 N/A. 코퍼스 공통(배치1·2 + 본 파일까지 퀴즈 미보유 파일 전원 동일). 보충 생성 목록이 최대 산출물.
- **L6 모호/부재**: 선행 챕터 명시 지목 부재로 L6=1 고착 — **코퍼스 전역 최다 반복 감점(지금까지 전 파일 L6=1)**. 본 파일은 형제 모듈 교차링크(버전↔MFA Delete↔복제)는 우수하나 챕터 간 브리지 없음. 생성 프롬프트에 "선행 챕터 id 명시 역참조 1개 이상 삽입" 규칙 추가 권장.
- **빈출도 태그(`freq`/`freqNote`) 재현**: B7 스키마 패턴 계속 누적(본 파일은 freqNote로 "무엇이 왜 출제되는지" 한 줄까지 부가 — 코퍼스 중 상세도 상위).

## 스키마 피드백 요약

- 기존 B7(빈출도 미터) 재현 + **freqNote(빈출 사유 한 줄)** 는 L1 문항 씨앗으로 직접 전환 가능(축2 SCHEMA_FEEDBACK의 `freqNote`와 동일). 신규: 각 모듈의 **Exam 콜아웃 = "시나리오 상황 → 정답 서비스/설정"** 구조가 사실상 문항의 정답·해설 원형 — 스키마 v1에 `examScenario{stem, answer, trap}` 필드를 두면 이 콜아웃을 문항으로 자동 승격하는 파이프라인 입력이 됨(제안, 직접 수정 안 함).
