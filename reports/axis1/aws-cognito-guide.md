## 수정 지시

1. **L6 → 2 승격 (핵심 감점, 실행 가능)**: 선행 챕터 명시 지목 3곳 추가.
   - `IdentityPools` 라인 1247–1249 "IAM 역할의 신뢰 정책(Trust Policy)은 Cognito Identity를 신뢰하도록 설정" → **"0-2장(IAM)에서 배운 신뢰 정책의 `Principal`에 `cognito-identity.amazonaws.com`을 지정하는 것과 동일 구조"** 식으로 선행 챕터·개념을 명시 지목.
   - `IdentityPools` CIP 흐름 "STS로 자격 증명 교환"(라인 1108·1228) → STS 임시 자격 증명을 다룬 선행 챕터를 **장 번호로** 역참조("STS 임시 자격 증명은 N-N장 참조").
   - `Overview` 라인 429–441 "IAM: 내부 사용자" 대비 → IAM 사용자/역할을 다룬 선행 챕터를 **명시 지목**(현재는 서비스 배경 언급 수준이라 1).
   - (주의) 라인 999 "398강 참고"는 동일 챕터 내부라 L6 가점 대상 아님 — 위 3곳처럼 **선행 챕터** 통합이어야 2.

2. **(L3 유지·강화, 선택)** 이미 2. `StepPlayer`/정책 JSON이 충분. 추가 개선 원하면 API Gateway Cognito Authorizer 카드(라인 606–619)에 실제 Authorization 헤더 예시(`Authorization: Bearer <access-token>`)를 코드 조각으로 붙이면 축2 수정지시 #2(베어러 토큰 키워드)와 L3를 동시 충족.

## 보충 생성 목록 (결손 성분)

퀴즈·해설 **전면 결손**이 핵심 결손. 파일 내 콜아웃이 문항 소재로 그대로 활용 가능(문항당 4지선다 + 오답 이유 해설 필수):

1. **CUP vs CIP 구분** — 소재: `Comparison` 비교표 7행(라인 1286–1306) + `한 줄 암기`(라인 1504). 산출물(JWT vs 임시 자격 증명)·게스트 지원 여부를 정답 축으로.
2. **키워드 매칭 시나리오** — 소재: 라인 442–446 `ExamTip` + 총정리 #2(라인 1543). "hundreds of users/mobile/SAML" → Cognito, 내부 직원 → IAM 오답지 대비.
3. **Policy Variable 파티셔닝** — 소재: 정책 JSON 블록(라인 1256–1268). `dynamodb:LeadingKeys`·`s3:prefix`·`${cognito-identity...:sub}` 빈칸/선택.
4. **ALB `OnUnauthenticatedRequest` 3옵션** — 소재: 라인 1017–1043. deny=HTTP 401, authenticate=기본값 구분(축2 확인 사실).
5. **Hosted UI 커스텀 도메인 ACM 인증서 위치** — 소재: 라인 738–742. 정답 us-east-1, 오답지에 리소스 리전.
6. **Lambda 트리거 시점 매칭** — 소재: 라인 632–641 8종 표. 시점↔트리거 매칭형.
7. **적응형 인증 Risk Score 대응** — 소재: 라인 750–789. Low/Medium/High → 통과/MFA/차단.
8. **JWT 구조** — 소재: 라인 806–838. Payload=클레임(sub UUID) 식별.
9. **(축2 위임 — 커버리지 갭 반영)** 토큰 3종(ID·Access·Refresh) 개별 용도·수명 문항은 **축2 수정지시 #1의 토큰 3종 블록 신설이 선행되어야** 출제 가능. 현 본문은 "JWT(ID·Access·Refresh)"로만 뭉뚱그려 문항 소재 자체가 없음 → **축2 소관으로 위임**(본문 보충 후 문항화).

## 반복 약점 메모

- **L6 명시 지목 부재** — 코퍼스 9번째 파일 연속 L6=1. 이 파일은 IAM/STS/신뢰 정책이라는 **명백한 선행 통합 지점을 배경 언급으로만 소비**(선행 챕터 번호 미지목). 생성 프롬프트에 "선행 챕터를 반드시 장 번호+개념명으로 명시 역참조하라"를 강제 규칙으로 추가 권고.
- 동일 챕터 내부 강 번호 참조("398강 참고")를 선행 지식 연결로 오인하지 않도록 채점 시 주의 — 이 파일이 대표 케이스.

## 스키마 피드백 요약

- `FreqBadge`(시험 빈출도 별점 1~5, 섹션별)와 말미 `ExamSummary` **빈출도 순 총정리**(라인 1536–1579) — 학습 우선순위·간격반복 신호로 유용한 v0 미표현 구조. "섹션별 빈출도 태그" + "빈출도 정렬 리뷰 스캐폴드" 필드 제안(퀴즈 난이도 분포 L7 설계 시 재사용 가능).
- `StepPlayer`(절차형 개념 단계 재생) 및 CUP vs CIP 비교표는 축2가 이미 docs/SCHEMA_FEEDBACK_AXIS2.md에 제안 기록 — 축1 관점에서도 절차형 인출·이중 서비스 대비에 유효하므로 중복 제안 없이 축2 기록에 병합.
